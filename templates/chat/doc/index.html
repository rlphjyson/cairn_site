Chat template

A mobile chat app built only from cairn_ui. This guide takes you from copy it in to talking to your own server in real time.

Overview

The template is a Flutter package, cairn_template_chat, that exposes one widget: ChatApp. It has a bottom dock with three tabs and three screens that open over them:

  • Chats – the conversation list: presence dots, previews, relative times, unread badges, a pinned section, an archive, search and a per-row menu (pin, mute, mark read or unread, archive, delete).
  • Thread – grouped bubbles with date separators, delivery ticks, reply quotes, photos, files, locations, links, emoji-only messages, reactions, a typing indicator, a growing composer, an attach sheet, a scroll-to-latest button and paging of older history.
  • New chat – contacts in alphabetical sections; start a one-to-one chat or build a group with chips and a name.
  • Info – contact or group details, shared photos, mute, members, leave or block.
  • Contacts and Profile tabs – the directory, and your own name, status line, availability and settings.

On a phone it is one column; from 700 px wide it is two panes (list left, thread right). It is organised as clean architecture by layer, then by feature, with flutter_bloc for state and get_it for dependency injection. Nothing is generated.

lib/
├─ chat_app.dart                   entry widget
├─ core/
│  ├─ infrastructure/di/           get_it registration (chat_injection.dart)
│  └─ presentation/                navigation cubit, shared widgets, ViewModel
├─ common/                         limits, reaction emoji, demo replies, date helpers
├─ data/
│  ├─ chat/remote/                 ChatRemoteDataSource, in-memory backend, bot, seed
│  └─ <feature>/repositories/      implement the domain interfaces
├─ domain/<feature>/               models, mappers, repository interfaces, use cases
└─ presentation/<feature>/         bloc, view models, views, widgets (+ shell/)
The one rule to remember

Dependencies point inwards: presentation → domain ← data. To change where messages come from you write one class that implements ChatRemoteDataSource and pass it to ChatApp. To change how they look you touch presentation/.

Install

A. As a package (recommended)

Keeping it a package means you can pull in fixes later with a version bump.

# pubspec.yaml
dependencies:
  cairn_ui: ^0.2.0
  cairn_template_chat:
    git:
      url: https://github.com/rlphjyson/cairn_site.git
      path: templates/chat
      ref: main            # pin a tag or commit for production

Or, from a local checkout: path: ../cairn_site/templates/chat. The package declares its images, so there is nothing to add to your pubspec.yaml.

B. Copy the source into your app

  1. Copy templates/chat/lib/ into lib/chat/ in your app and templates/chat/assets/images/ into your own assets folder.
  2. Add cairn_ui, flutter_bloc, get_it and equatable to your pubspec.yaml and declare the images under flutter: assets:.
  3. In lib/common/constants/chat_package.dart set static const String? name = null; so images resolve from your app instead of the package. If you keep the demo avatars, keep their folder as assets/images/, or change the paths in chat_seed.dart and demo_replies.dart.
  4. Rewrite the package:cairn_template_chat/… imports to your app’s package name (a find-and-replace). Files inside the template use relative imports, so only your own references change.

Mount it

The template reads colours, radii and type from CairnTheme, so the host app must provide one. Cairn leaves fontFamily unset in its tokens, so set yours.

import 'package:cairn_template_chat/cairn_template_chat.dart';
import 'package:cairn_ui/cairn_ui.dart';
import 'package:flutter/material.dart';

void main() => runApp(const MyApp());

class MyApp extends StatelessWidget {
  const MyApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      title: 'Acme Chat',
      theme: CairnTheme.materialTheme(
        CairnTheme.light.copyWith(fontFamily: 'Inter'),
      ),
      darkTheme: CairnTheme.materialTheme(
        CairnTheme.dark.copyWith(fontFamily: 'Inter'),
      ),
      home: const Scaffold(body: SafeArea(child: ChatApp())),
    );
  }
}

ChatApp fills whatever space its parent gives it (320 by 640 and up). Each instance creates its own dependency container and disposes it, so two chats on one screen never share state. It brings its own toaster, so copy, attach and save toasts work in any host.

Data model & JSON shapes

The data source returns decoded JSON, exactly what jsonDecode gives you. Mappers in domain/<feature>/mappers/ are the only code that reads these keys, so if your API names fields differently you change a mapper, never a view. Unknown keys are ignored and missing optional keys fall back to defaults, so a server can add fields without breaking the app. Timestamps are ISO-8601 strings.

Live events

Everything that happens without the app asking arrives as a JSON frame with a type, decoded by ChatEventMapper. Unknown types are ignored, so a newer server never breaks an older client.

typeOther keysEffect
messagemessageA message from someone else: appended to the open thread, counted as unseen when you are scrolled up, announced to screen readers; the list reorders and updates its badge.
message.updatedmessageA status or reaction change: replaces the message by id (this is how a double tick turns blue).
message.removedconversationId, messageIdRemoves it from the open thread.
typingconversationId, userId, typing (bool)Shows or hides the typing indicator and “typing...” in the header.
presencecontactUpdates presence dots and “last seen”.
conversationconversationIdSomething about a list entry changed; the list reloads. The id may be anything when you only want a refresh.

Replace the demo bot

Implement ChatRemoteDataSource and pass it as chatDataSource. It has nineteen methods: eleven for contacts and conversations, six for messages, events() and dispose(). Each documents the REST call it stands for. Nothing else in the template changes: cubits, views and tests keep working because they only see the repository interfaces.

The real-time extension point

Request/response methods are for history and actions. Everything that happens to an open thread without you asking (new messages, read receipts, typing, presence, list changes) must come from events(), a broadcast stream of decoded frames. Repositories expose it as MessageRepository.watchConversation, ConversationRepository.watchChanges and ContactRepository.watchPresence. The demo backs it with a StreamController; below it is a socket.

REST for history, WebSocket for live messages

Add http and web_socket_channel to your app. The class below is complete: it signs requests with a token, reconnects the socket with backoff, and nudges the list to reload after a reconnect so nothing stays stale.

import 'dart:async';
import 'dart:convert';
import 'dart:math' as math;

import 'package:cairn_template_chat/cairn_template_chat.dart';
import 'package:http/http.dart' as http;
import 'package:web_socket_channel/web_socket_channel.dart';

typedef Json = Map<String, Object?>;

class ChatHttpException implements Exception {
  const ChatHttpException(this.statusCode, this.path);

  final int statusCode;
  final String path;

  @override
  String toString() => 'ChatHttpException($statusCode $path)';
}

class RestChatDataSource implements ChatRemoteDataSource {
  RestChatDataSource({
    required this.baseUrl,     // https://api.example.com/v1
    required this.socketUrl,   // wss://api.example.com/v1/live
    required this.tokenProvider,
    http.Client? client,
  }) : _client = client ?? http.Client() {
    unawaited(_connect());
  }

  final String baseUrl;
  final String socketUrl;
  final Future<String> Function() tokenProvider;
  final http.Client _client;

  final StreamController<Json> _events = StreamController<Json>.broadcast();
  StreamSubscription<Object?>? _socket;
  Timer? _retry;
  int _attempt = 0;
  bool _closed = false;

  // ---- real time -----------------------------------------------------------

  Future<void> _connect() async {
    if (_closed) return;
    final String token = await tokenProvider();
    final WebSocketChannel channel = WebSocketChannel.connect(
      Uri.parse('$socketUrl?token=${Uri.encodeQueryComponent(token)}'),
    );
    _socket = channel.stream.listen(
      (Object? frame) {
        if (_attempt > 0) {
          // Reconnected: whatever happened meanwhile, refresh the list.
          _events.add(<String, Object?>{'type': 'conversation', 'conversationId': ''});
        }
        _attempt = 0;
        final Object? json = jsonDecode(frame! as String);
        if (json is Map<String, dynamic>) _events.add(Json.from(json));
      },
      onDone: _reconnect,
      onError: (Object _) => _reconnect(),
    );
  }

  void _reconnect() {
    if (_closed) return;
    final Duration wait = Duration(seconds: math.min(30, 1 << math.min(_attempt++, 5)));
    _retry = Timer(wait, () => unawaited(_connect()));
  }

  @override
  Stream<Json> events() => _events.stream;

  @override
  void dispose() {
    _closed = true;
    _retry?.cancel();
    unawaited(_socket?.cancel());
    _client.close();
    unawaited(_events.close());
  }

  /// Hand a frame to the app, for example from a push notification.
  void push(Json frame) => _events.add(frame);

  // ---- HTTP plumbing -------------------------------------------------------

  Future<Object?> _call(
    String method,
    String path, {
    Json? body,
    Map<String, String>? query,
  }) async {
    final Uri uri = Uri.parse('$baseUrl$path').replace(queryParameters: query);
    final http.Request request = http.Request(method, uri)
      ..headers['Authorization'] = 'Bearer ${await tokenProvider()}'
      ..headers['Content-Type'] = 'application/json';
    if (body != null) request.body = jsonEncode(body);
    final http.Response response = await http.Response.fromStream(
      await _client.send(request),
    );
    if (response.statusCode >= 400) {
      throw ChatHttpException(response.statusCode, path);
    }
    return response.body.isEmpty ? null : jsonDecode(response.body);
  }

  Future<Json> _json(String method, String path, {Json? body, Map<String, String>? query}) async =>
      Json.from(await _call(method, path, body: body, query: query) as Map<String, dynamic>);

  Future<List<Json>> _list(String path) async => <Json>[
    for (final Object? e in await _call('GET', path) as List<Object?>)
      Json.from(e! as Map<String, dynamic>),
  ];

  // ---- profile and contacts ------------------------------------------------

  @override
  Future<Json> fetchCurrentUser() => _json('GET', '/me');

  @override
  Future<List<Json>> fetchContacts() => _list('/contacts');

  @override
  Future<Json> patchProfile(Json changes) =>
      _json('PATCH', '/me', body: <String, Object?>{...changes}..removeWhere((String _, Object? v) => v == null));

  @override
  Future<void> blockContact(String contactId) =>
      _call('POST', '/contacts/$contactId/block');

  // ---- conversations -------------------------------------------------------

  @override
  Future<List<Json>> fetchConversations() => _list('/conversations');

  @override
  Future<Json?> fetchConversation(String id) async {
    try {
      return await _json('GET', '/conversations/$id');
    } on ChatHttpException catch (e) {
      if (e.statusCode == 404) return null;
      rethrow;
    }
  }

  @override
  Future<Json> openDirectConversation(String contactId) => _json(
    'POST', '/conversations',
    body: <String, Object?>{'type': 'direct', 'peerId': contactId},
  );

  @override
  Future<Json> createGroupConversation({
    required String name,
    required List<String> memberIds,
  }) => _json(
    'POST', '/conversations',
    body: <String, Object?>{'type': 'group', 'title': name, 'memberIds': memberIds},
  );

  @override
  Future<Json> patchConversation(String id, Json changes) => _json(
    'PATCH', '/conversations/$id',
    body: <String, Object?>{...changes}..removeWhere((String _, Object? v) => v == null),
  );

  @override
  Future<void> deleteConversation(String id) => _call('DELETE', '/conversations/$id');

  @override
  Future<void> leaveConversation(String id) => _call('POST', '/conversations/$id/leave');

  // ---- messages ------------------------------------------------------------

  @override
  Future<Json> fetchMessages(String conversationId, {String? beforeId, required int limit}) =>
      _json(
        'GET', '/conversations/$conversationId/messages',
        query: <String, String>{'limit': '$limit', if (beforeId != null) 'before': beforeId},
      );

  @override
  Future<Json> postMessage(Json body) =>
      _json('POST', '/conversations/${body['conversationId']}/messages', body: body);

  @override
  Future<void> postRead(String conversationId) =>
      _call('POST', '/conversations/$conversationId/read');

  @override
  Future<Json> postReaction(String conversationId, String messageId, String emoji) =>
      _json('PUT', '/messages/$messageId/reactions/${Uri.encodeComponent(emoji)}');

  @override
  Future<void> deleteMessage(String conversationId, String messageId) =>
      _call('DELETE', '/messages/$messageId');

  @override
  Future<List<Json>> fetchMedia(String conversationId) =>
      _list('/conversations/$conversationId/media');
}

Server contract in one paragraph

POST /conversations/{id}/messages returns the stored message (with a server id and status: sent) and must not also push it back to the sender as a message frame, or the sender sees it twice (the template ignores an echo only while its own send is in flight). Frames to other members are message; later changes to a message are message.updated. POST …/read should zero unread, flip the sender’s messages to read and emit message.updated to them.

Server-sent events instead of a socket

If your server speaks SSE, only the _connect part changes. Frames are the same JSON, one per data: line:

Future<void> _connect() async {
  if (_closed) return;
  final http.Request request = http.Request('GET', Uri.parse('$baseUrl/events'))
    ..headers['Accept'] = 'text/event-stream'
    ..headers['Authorization'] = 'Bearer ${await tokenProvider()}';
  final http.StreamedResponse response = await _client.send(request);
  _socket = response.stream
      .transform(utf8.decoder)
      .transform(const LineSplitter())
      .listen(
        (String line) {
          if (!line.startsWith('data:')) return;
          _attempt = 0;
          final Object? json = jsonDecode(line.substring(5).trim());
          if (json is Map<String, dynamic>) _events.add(Json.from(json));
        },
        onDone: _reconnect,
        onError: (Object _) => _reconnect(),
      );
}

Firebase (Cloud Firestore)

Firestore needs no socket: its snapshot listeners are the live channel. Model each conversation as a document with a messages sub-collection, and translate documents to the JSON shapes above. This is the core of an adapter; reactions, deletes and the profile calls follow the same read-translate-write pattern.

import 'dart:async';

import 'package:cairn_template_chat/cairn_template_chat.dart';
import 'package:cloud_firestore/cloud_firestore.dart';

typedef Json = Map<String, Object?>;

class FirestoreChatDataSource implements ChatRemoteDataSource {
  FirestoreChatDataSource(this._db, this._uid) {
    // New messages in any of my conversations, from now on.
    _subs.add(
      _db
          .collectionGroup('messages')
          .where('memberIds', arrayContains: _uid)
          .where('sentAt', isGreaterThan: Timestamp.now())
          .snapshots()
          .listen((QuerySnapshot<Json> snap) {
            for (final DocumentChange<Json> change in snap.docChanges) {
              final Json message = _message(change.doc);
              if (change.type == DocumentChangeType.added && message['senderId'] != _uid) {
                _events.add(<String, Object?>{'type': 'message', 'message': message});
              } else if (change.type == DocumentChangeType.modified) {
                _events.add(<String, Object?>{'type': 'message.updated', 'message': message});
              }
            }
          }),
    );
    // Any change to my conversations (last message, unread, flags).
    _subs.add(
      _db
          .collection('conversations')
          .where('memberIds', arrayContains: _uid)
          .snapshots()
          .listen((QuerySnapshot<Json> snap) {
            for (final DocumentChange<Json> change in snap.docChanges) {
              _events.add(<String, Object?>{
                'type': 'conversation',
                'conversationId': change.doc.id,
              });
            }
          }),
    );
  }

  final FirebaseFirestore _db;
  final String _uid;
  final StreamController<Json> _events = StreamController<Json>.broadcast();
  final List<StreamSubscription<Object?>> _subs = <StreamSubscription<Object?>>[];

  CollectionReference<Json> get _conversations => _db.collection('conversations');

  static String _iso(Object? t) => (t! as Timestamp).toDate().toIso8601String();

  Json _message(DocumentSnapshot<Json> doc) {
    final Json data = doc.data()!;
    return <String, Object?>{
      ...data,
      'id': doc.id,
      'conversationId': doc.reference.parent.parent!.id,
      'sentAt': _iso(data['sentAt']),
    };
  }

  Json _conversation(DocumentSnapshot<Json> doc) {
    final Json data = doc.data()!;
    final Map<String, Object?> unread = (data['unread'] as Map<String, Object?>?) ?? <String, Object?>{};
    final Map<String, Object?>? last = data['lastMessage'] as Map<String, Object?>?;
    final Map<String, Object?>? mine = (data['flags'] as Map<String, Object?>?)?[_uid] as Map<String, Object?>?;
    return <String, Object?>{
      ...data,
      ...?mine, // my pinned, muted, archived and markedUnread
      'id': doc.id,
      'unread': unread[_uid] ?? 0,
      'updatedAt': _iso(data['updatedAt']),
      'lastMessage': last == null
          ? null
          : <String, Object?>{...last, 'conversationId': doc.id, 'sentAt': _iso(last['sentAt'])},
    };
  }

  @override
  Future<List<Json>> fetchConversations() async {
    final QuerySnapshot<Json> snap = await _conversations
        .where('memberIds', arrayContains: _uid)
        .get();
    return <Json>[for (final QueryDocumentSnapshot<Json> d in snap.docs) _conversation(d)];
  }

  @override
  Future<Json> fetchMessages(String conversationId, {String? beforeId, required int limit}) async {
    final CollectionReference<Json> messages = _conversations.doc(conversationId).collection('messages');
    Query<Json> query = messages.orderBy('sentAt', descending: true).limit(limit + 1);
    if (beforeId != null) {
      query = query.startAfterDocument(await messages.doc(beforeId).get());
    }
    final List<QueryDocumentSnapshot<Json>> docs = (await query.get()).docs;
    return <String, Object?>{
      'hasMore': docs.length > limit,
      // Newest first from Firestore; the template wants oldest first.
      'messages': <Json>[
        for (final QueryDocumentSnapshot<Json> d in docs.take(limit).toList().reversed)
          if (!((d.data()['deletedFor'] as List<Object?>?) ?? <Object?>[]).contains(_uid)) _message(d),
      ],
    };
  }

  @override
  Future<Json> postMessage(Json body) async {
    final String id = body['conversationId']! as String;
    final DocumentReference<Json> ref = _conversations.doc(id).collection('messages').doc();
    final Json stored = <String, Object?>{
      'senderId': _uid,
      'text': body['text'],
      'replyTo': body['replyTo'],
      'attachment': body['attachment'],
      'reactions': <Object?>[],
      'status': 'sent',
      'sentAt': FieldValue.serverTimestamp(),
      'memberIds': (await _conversations.doc(id).get()).data()!['memberIds'],
    };
    await ref.set(stored);
    return _message(await ref.get(const GetOptions(serverTimestampBehavior: ServerTimestampBehavior.estimate)));
  }

  @override
  Future<void> postRead(String conversationId) =>
      _conversations.doc(conversationId).update(<String, Object?>{'unread.$_uid': 0});

  @override
  Stream<Json> events() => _events.stream;

  @override
  void dispose() {
    for (final StreamSubscription<Object?> s in _subs) {
      unawaited(s.cancel());
    }
    unawaited(_events.close());
  }

  // ---- people --------------------------------------------------------------

  Json _contact(DocumentSnapshot<Json> doc, {bool blocked = false}) {
    final Json data = doc.data()!;
    return <String, Object?>{
      ...data,
      'id': doc.id,
      'blocked': blocked,
      'lastSeen': data['lastSeen'] == null ? null : _iso(data['lastSeen']),
    };
  }

  DocumentReference<Json> get _me => _db.collection('users').doc(_uid);

  @override
  Future<Json> fetchCurrentUser() async => _contact(await _me.get());

  @override
  Future<List<Json>> fetchContacts() async {
    final Set<String> blocked = (await _me.collection('blocked').get()).docs
        .map((QueryDocumentSnapshot<Json> d) => d.id)
        .toSet();
    final QuerySnapshot<Json> users = await _db.collection('users').get();
    return <Json>[
      for (final QueryDocumentSnapshot<Json> d in users.docs)
        _contact(d, blocked: blocked.contains(d.id)),
    ];
  }

  @override
  Future<Json> patchProfile(Json changes) async {
    await _me.update(<String, Object?>{...changes}..removeWhere((String _, Object? v) => v == null));
    return _contact(await _me.get());
  }

  @override
  Future<void> blockContact(String contactId) =>
      _me.collection('blocked').doc(contactId).set(<String, Object?>{});

  // ---- conversations -------------------------------------------------------

  @override
  Future<Json?> fetchConversation(String id) async {
    final DocumentSnapshot<Json> doc = await _conversations.doc(id).get();
    return doc.exists ? _conversation(doc) : null;
  }

  @override
  Future<Json> openDirectConversation(String contactId) async {
    // One document per pair, so opening it twice finds the same chat.
    final String id = (<String>[_uid, contactId]..sort()).join('_');
    final DocumentReference<Json> ref = _conversations.doc(id);
    if (!(await ref.get()).exists) {
      final Json peer = _contact(await _db.collection('users').doc(contactId).get());
      await ref.set(<String, Object?>{
        'type': 'direct',
        'title': peer['name'],
        'avatar': peer['avatar'],
        'peerId': contactId,
        'memberIds': <String>[_uid, contactId],
        'updatedAt': FieldValue.serverTimestamp(),
      });
    }
    return _conversation(await ref.get(const GetOptions(serverTimestampBehavior: ServerTimestampBehavior.estimate)));
  }

  @override
  Future<Json> createGroupConversation({required String name, required List<String> memberIds}) async {
    final DocumentReference<Json> ref = _conversations.doc();
    await ref.set(<String, Object?>{
      'type': 'group',
      'title': name,
      'memberIds': <String>[_uid, ...memberIds],
      'updatedAt': FieldValue.serverTimestamp(),
    });
    return _conversation(await ref.get(const GetOptions(serverTimestampBehavior: ServerTimestampBehavior.estimate)));
  }

  @override
  Future<Json> patchConversation(String id, Json changes) async {
    // Flags are per user: flags.<uid>.pinned and so on.
    await _conversations.doc(id).update(<String, Object?>{
      for (final MapEntry<String, Object?> e in changes.entries)
        if (e.value != null) 'flags.$_uid.${e.key}': e.value,
      if (changes['markedUnread'] == false) 'unread.$_uid': 0,
    });
    return _conversation(await _conversations.doc(id).get());
  }

  @override
  Future<void> deleteConversation(String id) => leaveConversation(id);

  @override
  Future<void> leaveConversation(String id) =>
      _conversations.doc(id).update(<String, Object?>{'memberIds': FieldValue.arrayRemove(<String>[_uid])});

  // ---- messages ------------------------------------------------------------

  @override
  Future<Json> postReaction(String conversationId, String messageId, String emoji) async {
    final DocumentReference<Json> ref = _conversations.doc(conversationId).collection('messages').doc(messageId);
    await _db.runTransaction<void>((Transaction tx) async {
      final List<Object?> reactions = List<Object?>.of((await tx.get(ref)).data()!['reactions'] as List<Object?>);
      final int at = reactions.indexWhere((Object? r) => (r! as Map<String, Object?>)['emoji'] == emoji);
      if (at < 0) {
        reactions.add(<String, Object?>{'emoji': emoji, 'userIds': <String>[_uid]});
      } else {
        final Map<String, Object?> r = Map<String, Object?>.of(reactions[at]! as Map<String, Object?>);
        final List<String> users = List<String>.of((r['userIds']! as List<Object?>).cast<String>());
        users.contains(_uid) ? users.remove(_uid) : users.add(_uid);
        users.isEmpty ? reactions.removeAt(at) : reactions[at] = <String, Object?>{'emoji': emoji, 'userIds': users};
      }
      tx.update(ref, <String, Object?>{'reactions': reactions});
    });
    return _message(await ref.get());
  }

  @override
  Future<void> deleteMessage(String conversationId, String messageId) =>
      _conversations.doc(conversationId).collection('messages').doc(messageId).update(
        <String, Object?>{'deletedFor': FieldValue.arrayUnion(<String>[_uid])},
      );

  @override
  Future<List<Json>> fetchMedia(String conversationId) async {
    final QuerySnapshot<Json> snap = await _conversations
        .doc(conversationId)
        .collection('messages')
        .where('attachment.type', isEqualTo: 'image')
        .orderBy('sentAt')
        .get();
    return <Json>[for (final QueryDocumentSnapshot<Json> d in snap.docs) _message(d)];
  }
}
Security rules and denormalisation

Store memberIds on each message (as above) so one collection-group query and one security rule (request.auth.uid in resource.data.memberIds) cover reads. Keep per-user flags (pinned, muted, archived) in a map keyed by user id on the conversation, and pick yours out in _conversation, as is done for unread. Typing and presence are best kept in Realtime Database (or a short-lived document) and translated to typing and presence frames.

The app-icon badge is your server’s job: it knows each user’s total unread count and sends it in the push payload. The in-app dock badge is ConversationInbox.unreadTotal: unread messages in conversations that are neither muted nor archived, counting a conversation you marked unread as one.

Attachments upload

In the demo, the + button opens a sheet (photo library, camera, file, location) and any choice toasts that it is a demo. The template does not ship pickers, so it stays free of platform plugins. To make it real, replace the body of _attach in presentation/thread/views/thread_view.dart. A message with an Attachment is sent through the same path as text, so replies, ticks, reactions and the preview in the list already work.

Future<void> _attach() async {
  final AttachOption? option = await showAttachSheet(context);
  if (option == null || !mounted) return;
  final ThreadCubit thread = context.read<ThreadCubit>();

  switch (option) {
    case AttachOption.photo:
    case AttachOption.camera:
      final XFile? picked = await ImagePicker().pickImage(
        source: option == AttachOption.photo ? ImageSource.gallery : ImageSource.camera,
        maxWidth: 1600,
      );
      if (picked == null) return;
      final Upload up = await uploads.upload(picked.path); // your service
      await thread.send(
        '',
        attachment: Attachment(
          kind: AttachmentKind.image,
          url: up.url,
          aspectRatio: up.width / up.height,
        ),
      );
    case AttachOption.file:
      final FilePickerResult? result = await FilePicker.platform.pickFiles();
      final PlatformFile? file = result?.files.single;
      if (file == null || file.path == null) return;
      final Upload up = await uploads.upload(file.path!);
      await thread.send(
        '',
        attachment: Attachment(
          kind: AttachmentKind.file,
          url: up.url,
          name: file.name,
          sizeBytes: file.size,
        ),
      );
    case AttachOption.location:
      final Position here = await Geolocator.getCurrentPosition();
      await thread.send(
        '',
        attachment: Attachment(
          kind: AttachmentKind.location,
          name: '${here.latitude.toStringAsFixed(4)}, ${here.longitude.toStringAsFixed(4)}',
        ),
      );
  }
}

A typical upload service does POST /uploads (multipart) and returns { "url": ..., "width": ..., "height": ... }; the message then carries the URL. Two refinements worth making: show a progress indicator while uploading (upload first, then send, so a failed upload never leaves a ghost message), and extend Attachment with latitude and longitude (plus the key in MessageMapper) so a location bubble can open a map.

Photos are drawn with Image from chatImage(...) (lib/core/presentation/chat_images.dart): an http(s) URL becomes a NetworkImage, anything else an asset. Swap it for CachedNetworkImageProvider there to get a disk cache everywhere at once.

Read receipts & presence

Ticks

Your own messages show a clock while sending, one tick when sent, two blue ticks when read and “Not sent” when failed. The thread sets sending locally and replaces the message with the server’s when the call returns. read arrives as a message.updated frame after the other person’s app calls MarkRead.

MarkRead runs when a thread opens, and again whenever a message arrives while you are at the bottom of the list or you scroll back down (ThreadCubit.setAtBottom). It does not run for messages that arrive while you are scrolled up; they are counted on the scroll-to-latest button instead.

The “Read receipts” switch

The switch on the Profile tab is kept in memory in ProfileCubit. To honour it, pass it to the server: make MarkRead take a sendReceipt flag, add it to MessageRepository.markRead and the POST …/read body, and read ProfileCubit.state.readReceipts where the thread calls it.

Presence and last seen

The dot comes from Contact.presence (green online, amber away, red do not disturb, none when offline). A thread header shows the label, or “last seen 12m ago” from lastSeen. Presence changes arrive as presence frames and update every dot at once through ContactsCubit. Your own choice on the Profile tab is PATCH /me; your server decides what others see (typically it sets offline and lastSeen when your socket closes).

Typing

Incoming typing frames drive the dots and the header text. Sending your own typing is not wired up: add sendTyping(conversationId) to MessageRepository, call it from the composer’s onChanged at most every three seconds, and send PUT /conversations/{id}/typing from the data source.

Pagination

A thread opens with the newest ChatLimits.pageSize messages (30). When the list is scrolled to within 400 px of its older end, or the loaded messages do not fill the screen, ThreadCubit.loadOlder asks for the page before the oldest message by id (GET …/messages?before=<id>&limit=30) and prepends it; hasMore: false stops the requests and shows “Start of the conversation”. The list is a reversed ListView with stable keys, so prepending does not move what you are reading.

  • Pages are oldest first; GetMessages sorts and removes duplicates anyway, so a sloppy backend cannot scramble a thread.
  • Use ids (or opaque cursors) rather than offsets: messages arriving while you page would shift offsets.
  • Change the page size in common/constants/chat_limits.dart.

go_router deep links to a thread

The template keeps its own navigation so it runs in any app. To make a thread addressable, give ChatApp the conversation the URL names and tell the router what the user opens. Use one route with a query parameter, so changing the conversation updates the same ChatApp instead of remounting it.

final GoRouter router = GoRouter(
  routes: <RouteBase>[
    GoRoute(
      path: '/chat',
      builder: (BuildContext context, GoRouterState state) {
        final String? id = state.uri.queryParameters['c'];
        return Scaffold(
          body: SafeArea(
            child: ChatApp(
              chatDataSource: chatSource,
              currentUserId: session.userId,
              initialConversationId: id,
              // Keep the address bar in step with what is open.
              onConversationOpened: (String? open) {
                if (open == id) return;
                context.go(open == null ? '/chat' : '/chat?c=$open');
              },
            ),
          ),
        );
      },
    ),
  ],
);

Opening /chat?c=c_mina (a push, a shared link) opens the thread. Tapping a conversation inside the app calls onConversationOpened, the router updates the URL, the builder runs again with the same id, and ChatApp sees nothing to do. The back button of a thread closes it and reports null, which returns the URL to /chat. Info and new chat screens are not in the URL; add a second parameter the same way if you need that.

To replace the navigation cubit entirely, keep every view and replace ChatNavigationCubit (selectTab, openThread, openInfo, openNewChat, back, clear, closeConversation) with calls to your router, and render ThreadView(conversationId: …, showBack: true), InfoView and NewChatView from your routes.

Two-pane layout

ChatShell (presentation/shell/chat_shell.dart) chooses the layout from the width it is given, not from the device:

WidthLayout
< 700One column. The tab fills the screen above a dock; opening a thread, info or new chat covers the tab and the dock, and Back returns.
≥ 700A 320 px pane on the left with the tab and the dock, a hairline, and the open screen on the right (or “Select a conversation”). The thread has no back button, the open conversation is highlighted in the list, and opening another one swaps the right pane.

Both numbers are in common/constants/chat_limits.dart (twoPaneBreakpoint, listPaneWidth). Because the choice is by width, a phone frame in a web page (such as CairnMockupPhone) gets the phone layout and a wide window gets two panes, with no platform checks. On very wide screens the right pane simply grows; wrap ChatApp in a ConstrainedBox if you prefer a maximum width.

Localisation

All visible text is English string literals in the views, and all dates are formatted by two small files. That keeps the template readable; to localise it:

  1. Strings. Search presentation/ and core/presentation/ for Text(' and label:; move each into your AppLocalizations (or a ChatStrings class) and pass the localisations in through the widget tree or read them with AppLocalizations.of(context). Domain messages (GroupProblem.message) are plain strings: map the enum in the view instead.
  2. Dates. formatDayLabel, weekdayShort, dayMonth and formatClock (common/utils/dates.dart), and FormatRelativeTime (“12m”, “Yesterday”, “last seen…”) are pure functions with the clock passed in. Reimplement them with intl (DateFormat.MMMEd(locale), DateFormat.Hm(locale)); their unit tests show the cases to keep.
  3. Plurals. “1 photo / 3 photos”, “1 chat / 2 chats”, “1 new message” are written with a small conditional in the views; use Intl.plural.
  4. Right-to-left. Not mirrored. CairnChatBubble aligns sent bubbles to the physical right, and a few paddings use left/right. Treat RTL as work to do and test, not a switch.

The suite has three layers: domain (ordering, search, paging, grouping, date labels, relative time, validation, reactions, mappers, seed, bot), session (cubits through the real container, no widgets) and widget tests that mount ChatApp at 320, 360, 390 and 700 pixels in light and dark and drive the whole journey.

  • Fix the clock and the latency: ChatApp(now: () => DateTime(2026, 10, 9, 12), replyLatency: Duration.zero). With zero latency the bot answers on the next event-loop turns; pump a few short frames and it has replied.
  • Never pumpAndSettle. Cairn has repeating animations (spinner, skeleton, typing dots), so it never returns. Pump tester.pump(const Duration(milliseconds: 100)) a handful of times.
  • Use real font metrics. test/flutter_test_config.dart loads Geist when it can find it, and the harness sets fontFamily: 'Geist' on the test theme; otherwise Flutter’s test font draws every glyph as a wide box and reports overflows real text never has. With your own font, load it there the same way.
  • Push events by hand. test/support/fake_sources.dart has WrappedSource, a data source that wraps the in-memory one and adds push(frame), a gate that holds the list back (to see skeletons) and a switch that makes sending fail. It is also the smallest example of a custom ChatRemoteDataSource.
  • Test your backend class by pointing http.Client at a MockClient and asserting on the JSON it returns; the mappers already have round-trip tests for every shape.

Troubleshooting

My messages appear on the left

currentUserId does not match the senderId your server puts on your messages. Pass the same id to ChatApp (and to the in-memory source, if you use it).

A message shows twice

Your server sent a message frame to the sender as well as returning it from the POST. Send the frame only to the other members, or make the frame carry the same id as the POST response; the template replaces by id.

Nothing updates until I reopen the screen

events() must be a broadcast stream (StreamController.broadcast()), and frames must be Map<String, Object?>: convert jsonDecode’s Map<String, dynamic> with Json.from(...) (the REST example does).

The list never leaves its skeleton

fetchConversations threw or never completed. A failure on the first load shows “Could not load your chats” with a retry; a request that hangs shows skeletons forever, so give your HTTP client a timeout.

Images are missing after I copied the source

Set ChatPackage.name = null and declare the assets in your own pubspec.yaml (see Install).

Emoji draw as empty boxes

The font has no emoji and the platform provided no fallback (common in tests and some web builds). Add a colour emoji font to CairnTheme.fontFamilyFallback.

“No ChatScope above this context”

A view or ViewModelBuilder was built outside ChatApp. Mount ChatApp (it provides the scope), or wrap your tree in a ChatScope with a locator from createChatLocator.

“A Timer is still pending” in a test

You passed chatDataSource and did not dispose it. A data source you pass in is yours: addTearDown(source.dispose). The built-in one is disposed with the app.

Everything is black and white and unstyled

The host app has no CairnTheme. Use CairnTheme.materialTheme(...) or add CairnTheme.light to ThemeData.extensions.

Toasts do nothing

A toast needs a CairnToaster above its caller. ChatApp provides one for its own screens; sheets and dialogs open on the root navigator, so the template shows toasts after they close.
