SaaS landing page template

A one-page landing site built only from cairn_ui: ten sections, light and dark, phone to desktop. Clean architecture, flutter_bloc and get_it. All copy is data you can change in one place. This page is the install guide, the tutorial and the reference.

Flutter webcairn_ui ^0.2.0No code generationWorks offline

#Overview and architecture

This is a one-page SaaS landing site built only from cairn_ui. It is a Flutter package with a single entry widget, LandingApp. It fills whatever space its parent gives it, adapts to that width (phone, tablet or desktop), follows light and dark through CairnTheme, and keeps every word, number, link and image reference in JSON-shaped data so you can rebrand it without touching a widget.

The demo product is Kestrel, an invented project planner. Nothing in it is a real brand: the logo cloud is drawn from text, the portraits are stock photos of nobody in particular, and the dashboard in the hero is assembled from Cairn widgets.

Architecture

Clean architecture with the layers at the top level and features inside each layer. State is flutter_bloc cubits, dependency injection is get_it with explicit registration (no code generation).

Layout of lib/
lib/
  landing_app.dart               entry widget LandingApp (owns its own GetIt)
  cairn_template_landing.dart    barrel: LandingApp and the extension points
  core/
    infrastructure/di/           landing_injection.dart: the container
    presentation/
      navigation/                LandingNavigationCubit (scroll intent)
      widgets/                   SectionFrame, SectionHeader, grids, Reveal
      content_cubit.dart         ContentCubit<T> + ContentViewModel<T>
      layout.dart                breakpoints, LandingViewport
      view_model.dart            ViewModel, ViewModelBuilder, LandingScope
  common/
    constants/                   section_ids.dart, landing_package.dart
    utils/                       json.dart, price_format.dart
  data/<feature>/
    remote/                      data source interface + InMemory content
    repositories/                implement the domain interfaces
  domain/<feature>/
    models/                      plain Equatable objects
    mappers/                     decoded JSON -> models
    repositories/                interfaces
    use_cases/                   one job each
  presentation/<feature>/
    bloc/  view_models/  views/  widgets/
  presentation/shell/            providers, navbar, scroll frame, page order

Features: site, hero, logos, features, how_it_works, stats, testimonials, pricing, faq, waitlist, footer.

Rules

  1. Dependencies point inwards. Presentation depends on domain; data depends on domain; domain depends on nothing but Dart and common.
  2. Views never touch the container. A section that needs a screen-scoped cubit uses ViewModelBuilder<T> (content sections go through ContentView<T>, which wraps it). Session cubits are read with context.read.
  3. Two kinds of cubit. Session cubits (navigation, site info) are lazy singletons provided once with BlocProvider.value; only the container closes them. Screen cubits (every section, the pricing toggle, the waitlist form) are created by a view model that closes them in dispose.
  4. Content-only sections share one generic cubit. ContentCubit<T> loads a use case's result. pricing and waitlist have behaviour, so they have their own cubits.
  5. Features do not import each other's presentation. The navbar and footer read the brand from the session ContentCubit<SiteInfo>.
  6. No code generation. Registrations are written out in landing_injection.dart.

How a section gets its words

InMemoryHeroRemoteDataSource.fetchHero()   // a const JSON map
        |
HeroRepositoryImpl.getHero()               // data layer: mapHero(json)
        |
GetHero()                                  // use case
        |
ContentCubit<HeroContent>.load()           // created by a ContentViewModel
        |
HeroView -> ContentView<HeroContent>       // builds the section once loaded

To change a word you edit the JSON. To change where the words come from you write a different data source. Nothing above the data layer notices.

#Install

A. As a package (recommended)

Path dependency, for a template that sits next to your app:

pubspec.yaml
dependencies:
  cairn_template_landing:
    path: ../templates/landing

Or from git, if you have pushed it to a repository (adjust url and path):

pubspec.yaml
dependencies:
  cairn_template_landing:
    git:
      url: https://github.com/your-org/your-repo.git
      path: templates/landing
      ref: main
flutter pub get

The photographs travel with the package and resolve as packages/cairn_template_landing/assets/images/.... Nothing to declare in your own pubspec.

Package mode is the right choice when you want to use the template and change its content through data overrides. If you want to edit its widgets, copy it instead.

B. By copying lib/ and assets/

  1. Copy templates/landing/lib/ into your app, for example to lib/landing/.
  2. Copy templates/landing/assets/images/ to assets/images/ and declare it:
    pubspec.yaml
    flutter:
  uses-material-design: true
  assets:
    - assets/images/
  3. Tell the template the assets belong to your app. In lib/landing/common/constants/landing_package.dart:
    landing_package.dart
    abstract final class LandingPackage {
  // ignore: unnecessary_nullable_for_final_variable_declarations
  static const String? name = null;
}
  4. Add the four dependencies from Requirements and run flutter pub get.
  5. Rewrite the imports. Inside the copy everything uses relative imports, so only the entry point changes: import 'landing/landing_app.dart';.

Copy NOTICE.md along with the images; the licence asks for nothing, but the credits belong with the files.

#Mount it

The template needs a MaterialApp (or any app with a Navigator, Overlay and MediaQuery) above it, and a theme that carries CairnTheme. A complete main.dart:

lib/main.dart
import 'package:cairn_template_landing/cairn_template_landing.dart';
import 'package:cairn_ui/cairn_ui.dart';
import 'package:flutter/material.dart';

void main() => runApp(const KestrelSite());

class KestrelSite extends StatelessWidget {
  const KestrelSite({super.key});

  @override
  Widget build(BuildContext context) {
    // Use your own font family here; null inherits the platform default.
    final CairnTheme light = CairnTheme.light.copyWith(fontFamily: 'Geist');
    final CairnTheme dark = CairnTheme.dark.copyWith(fontFamily: 'Geist');

    return MaterialApp(
      title: 'Kestrel',
      debugShowCheckedModeBanner: false,
      theme: CairnTheme.materialTheme(light),
      darkTheme: CairnTheme.materialTheme(dark),
      themeMode: ThemeMode.system,
      home: Scaffold(
        body: LandingApp(
          // Receives every content link that does not start with '#'.
          onLink: (String href) => debugPrint('open $href'),
        ),
      ),
    );
  }
}

If you declare a font, list it in your pubspec:

pubspec.yaml
flutter:
  fonts:
    - family: Geist
      fonts:
        - asset: fonts/Geist-Regular.ttf
        - asset: fonts/Geist-Medium.ttf
          weight: 500
        - asset: fonts/Geist-SemiBold.ttf
          weight: 600
        - asset: fonts/Geist-Bold.ttf
          weight: 700

The entry widget

ParameterTypeMeaning
onLinkValueChanged<String>?Called with the href of any content link that is not a # anchor: sign in, plan buttons, footer links, mailto:. If null, those links do nothing.
initialSectionString?A section id to scroll to about 600 ms after the page first builds. Use it for deep links such as /pricing.
onSectionChangedValueChanged<String>?Told the id of the section at the top of the viewport whenever it changes.
overridesvoid Function(GetIt)?Runs once before anything resolves: swap a data source, repository or use case for your own. See Wire the waitlist.

Links that start with # are handled by the template itself: #pricing scrolls to the section whose id is pricing. Ids are listed in SectionIds.

Mounting somewhere other than the whole screen

The page measures the space it is given, not the screen, so it works in a frame:

SizedBox(
  width: 420,
  height: 800,
  child: const LandingApp(),   // lays out as a phone page
)

It always needs a bounded height, because it is a scroll view inside a column. Put it in an Expanded, a SizedBox or a Scaffold body, never in an unbounded Column child or another scroll view.

#Update the content

All copy lives in lib/data/<feature>/remote/<feature>_remote_data_source.dart, in a class named InMemory<Feature>RemoteDataSource. In copy mode edit those files directly. In package mode you cannot edit them, so you give LandingApp.overrides your own data source (see below).

1. Rebrand

  1. Open data/site/remote/site_remote_data_source.dart. Change brandName, tagline and brandIcon. The navbar, the menu sheet and the footer all read it. 
    static const JsonMap _json = <String, Object?>{
  'brandName': 'Acme',
  'brandIcon': 'bolt',
  'tagline': 'Invoices that send themselves.',
  ...
  2. Search the other data files for Kestrel and kestrel.example. The name appears in the hero mockup URL, testimonials, FAQ answers, footer and contact links.
  3. Change copyright in footer_remote_data_source.dart.
  4. Replace the six logo wordmarks in logos_remote_data_source.dart with your customers' names (as text), or leave invented ones.

2. Change the hero copy

In data/hero/remote/hero_remote_data_source.dart:

  'href': '#features',

'headline': 'Get paid faster, with no chasing.',

To point a button at your real sign-up, use a non-anchor href such as /signup or https://app.acme.example/signup and handle it in onLink.

The dashboard in the browser frame is drawn from the visual object (project name, three metrics, seven bars, three tasks). Edit the numbers and names; the layout adapts. If you would rather show a real screenshot, replace the ProductMockup in presentation/hero/views/hero_view.dart with a LandingPhoto inside a CairnMockupBrowser.

3. Add or remove features

Cards are the entries in items in features_remote_data_source.dart:

<String, Object?>{
  'icon': 'notifications',
  'title': 'Smart reminders',
  'description': 'Polite nudges that stop the moment an invoice is paid.',
  'tag': 'New',            // optional badge
},

7. Navigation links and section ids

Navbar links are navLinks in the site file. A link whose href is #id scrolls to the section with that id, and is highlighted while that section is at the top.

The ids are in common/constants/section_ids.dart; the page order is in presentation/shell/landing_page.dart. To add a section:

  1. Add an id to SectionIds and to SectionIds.all in the position it will have on the page.
  2. Build a widget for it (a SectionFrame with your content).
  3. Add keyed(SectionIds.pricingFaq, const MyView()) at the same position in LandingPage.
  4. Link to it with 'href': '#your-id'.

To remove a section, delete its line from LandingPage, its id from SectionIds.all, and any links to it. A link to an id that no longer exists does nothing.

A section's navbar highlight uses the same ids, so the navbar link #how-it-works lights up while the how-it-works section is at the top. Sections that have no navbar link (logos, stats, waitlist) simply leave the previous link lit.

Changing content in package mode

If you depend on the package and cannot edit its files, write your own data source and hand it over with overrides. Reuse the shipped one for everything you do not change:

import 'package:cairn_template_landing/cairn_template_landing.dart';
import 'package:get_it/get_it.dart';

class AcmeHeroData implements HeroRemoteDataSource {
  const AcmeHeroData();

  @override
  Future<JsonMap> fetchHero() async => <String, Object?>{
    // The full shape: see the JSON reference below.
    'announcement': <String, Object?>{'label': 'New', 'href': '#features'},
    'headline': 'Get paid faster, with no chasing.',
    ...
  };
}

LandingApp(
  overrides: (GetIt locator) => locator
    ..unregister<HeroRemoteDataSource>()
    ..registerLazySingleton<HeroRemoteDataSource>(AcmeHeroData.new),
)

A trick that avoids retyping a whole file: fetch the demo JSON and change a few keys.

class AcmePricing implements PricingRemoteDataSource {
  const AcmePricing();

  @override
  Future<JsonMap> fetchPricing() async {
    final JsonMap demo = await const InMemoryPricingRemoteDataSource().fetchPricing();
    return <String, Object?>{...demo, 'yearlyDiscountPercent': 25, 'currency': '€'};
  }
}

The images in the demo JSON are package assets. Your own assets live in your app; see Replace images.

JSON shape reference

Every file exposes one method returning a decoded JSON map (Map<String, Object?>). A required key that is missing or has the wrong type throws a FormatException that names the key, for example Expected a string at "headline", got null. Optional keys are marked opt. Link means {"label": String, "href": String}; an href starting with # scrolls to that section id, anything else goes to onLink. icon is a name from the icon list. asset is a path such as assets/images/team-meeting.jpg.

Package mode

Your images live in your app, but the template resolves paths against its own package. Two options:

  1. Replace the files inside the package (keep the names), if you vendor it.
  2. Use a full-package asset path from your data override: a path in the JSON is resolved as AssetImage(path, package: LandingPackage.name). If you copy the template (mode B) and set LandingPackage.name to null, paths resolve in your own app, which is the simplest way to use your own pictures.

Copy mode

  1. Drop the file in assets/images/ (it is already declared as a folder).
  2. Reference it from the data: 'image': 'assets/images/dashboard-shot.png'.
  3. Write a real imageAlt for spotlights. Avatars take their accessible name from the person's name.

Choosing good images

  • Spotlights: photographs with the subject away from the edges; they are cropped to fit. Keep them under about 300 KB (1400 px wide is enough).
  • Avatars: square, face centred, no text or logos.
  • Avoid images with readable brand logos or watermarks.

If an image fails to load (wrong path), the box shows the theme's muted colour instead of a hole or a red error.

The photos are from Pexels; see NOTICE.md for each file's source. Update that file when you swap them.

#Wire the waitlist to a real service

The form is presentation/waitlist/. It validates with the ValidateEmail use case, submits with JoinWaitlist, and keeps its state in WaitlistCubit (idle, submitting, success, invalid, failure). The only thing that talks to a service is one method:

abstract interface class WaitlistRemoteDataSource {
  Future<JsonMap> fetchWaitlist();          // the copy of the section
  Future<JsonMap> submit(String email);     // the signup
}

submit returns decoded JSON {"position": 1284}, or throws a WaitlistException whose message is shown to the visitor (inline and in a toast). Any other exception becomes a generic "try again" message. The demo implementation waits 700 ms and refuses addresses ending in @fail.example so you can see the error state.

The recipe is always the same: write a data source, register it with overrides (or in landing_injection.dart in copy mode).

A. Your own REST endpoint

Add http to your app (flutter pub add http), then:

rest_waitlist.dart
import 'dart:convert';

import 'package:cairn_template_landing/cairn_template_landing.dart';
import 'package:get_it/get_it.dart';
import 'package:http/http.dart' as http;

class RestWaitlistRemoteDataSource implements WaitlistRemoteDataSource {
  RestWaitlistRemoteDataSource(this._client, this._endpoint);

  final http.Client _client;
  final Uri _endpoint;

  // Keep the demo copy; only the signup changes.
  final WaitlistRemoteDataSource _copy = InMemoryWaitlistRemoteDataSource();

  @override
  Future<JsonMap> fetchWaitlist() => _copy.fetchWaitlist();

  @override
  Future<JsonMap> submit(String email) async {
    final http.Response res = await _client
        .post(
          _endpoint,
          headers: <String, String>{'content-type': 'application/json'},
          body: jsonEncode(<String, String>{'email': email}),
        )
        .timeout(const Duration(seconds: 10));

    if (res.statusCode == 409) {
      throw const WaitlistException('You are already on the list.');
    }
    if (res.statusCode >= 400) {
      throw const WaitlistException(
        'We could not add you right now. Please try again in a moment.',
      );
    }
    // Your API answers {"position": 1284}.
    return (jsonDecode(res.body) as Map<String, Object?>);
  }
}

// In main():
final http.Client client = http.Client();

LandingApp(
  overrides: (GetIt locator) => locator
    ..unregister<WaitlistRemoteDataSource>()
    ..registerLazySingleton<WaitlistRemoteDataSource>(
      () => RestWaitlistRemoteDataSource(
        client,
        Uri.parse('https://api.acme.example/v1/waitlist'),
      ),
    ),
)

If your API does not return a position, return {'position': 0} and remove the badge in waitlist_form.dart (_Success), or compute the position in the data source.

The endpoint must allow your site's origin (CORS), or the browser blocks the request.

B. Firebase (Cloud Firestore)

Set up FlutterFire as usual (flutterfire configure, Firebase.initializeApp() before runApp), add cloud_firestore, then:

firestore_waitlist.dart
import 'package:cairn_template_landing/cairn_template_landing.dart';
import 'package:cloud_firestore/cloud_firestore.dart';

class FirestoreWaitlistRemoteDataSource implements WaitlistRemoteDataSource {
  FirestoreWaitlistRemoteDataSource(this._db);

  final FirebaseFirestore _db;
  final WaitlistRemoteDataSource _copy = InMemoryWaitlistRemoteDataSource();

  @override
  Future<JsonMap> fetchWaitlist() => _copy.fetchWaitlist();

  @override
  Future<JsonMap> submit(String email) async {
    final String id = email.trim().toLowerCase();
    final DocumentReference<Map<String, dynamic>> doc =
        _db.collection('waitlist').doc(id);
    try {
      await _db.runTransaction((Transaction tx) async {
        if ((await tx.get(doc)).exists) {
          throw const WaitlistException('You are already on the list.');
        }
        tx.set(doc, <String, Object?>{
          'email': id,
          'createdAt': FieldValue.serverTimestamp(),
        });
      });
    } on FirebaseException {
      throw const WaitlistException(
        'We could not add you right now. Please try again in a moment.',
      );
    }
    final AggregateQuerySnapshot count =
        await _db.collection('waitlist').count().get();
    return <String, Object?>{'position': count.count ?? 1};
  }
}

LandingApp(
  overrides: (GetIt locator) => locator
    ..unregister<WaitlistRemoteDataSource>()
    ..registerLazySingleton<WaitlistRemoteDataSource>(
      () => FirestoreWaitlistRemoteDataSource(FirebaseFirestore.instance),
    ),
)

Lock the collection down so visitors can add themselves but never read the list:

firestore.rules
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /waitlist/{email} {
      allow create: if request.resource.data.keys().hasOnly(['email', 'createdAt'])
                    && request.resource.data.email is string
                    && request.resource.data.email.size() < 255;
      allow read, update, delete: if false;
    }
  }
}

With these rules the get inside the transaction and the count() query are refused. Either allow get (leaks which emails exist) or move the duplicate check and the position into a Cloud Function and use option A. For a simple list, drop the transaction and use doc.set(...) with SetOptions(merge: true) and return {'position': 0}.

C. Mailchimp (or any email provider)

Never put a Mailchimp API key in a Flutter app: it ships to every visitor. Put a tiny server in front and use option A against it. For example a Cloud Function or serverless handler:

server/waitlist.js
// Node.js, e.g. a Cloud Function or Netlify function
export async function handler(req) {
  const { email } = JSON.parse(req.body);
  const dc = process.env.MAILCHIMP_DC;            // e.g. "us21"
  const res = await fetch(
    `https://${dc}.api.mailchimp.com/3.0/lists/${process.env.MAILCHIMP_LIST}/members`,
    {
      method: 'POST',
      headers: {
        'content-type': 'application/json',
        authorization: `Bearer ${process.env.MAILCHIMP_KEY}`,
      },
      body: JSON.stringify({ email_address: email, status: 'pending' }), // double opt-in
    },
  );
  if (res.status === 400) {
    const body = await res.json();
    if (body.title === 'Member Exists') return { statusCode: 409, body: '{}' };
  }
  if (!res.ok) return { statusCode: 502, body: '{}' };
  return { statusCode: 200, body: JSON.stringify({ position: 0 }) };
}

The Flutter side is exactly the RestWaitlistRemoteDataSource above, pointing at that function. ConvertKit, Loops, Buttondown and similar services have the same shape: a server-side call with a secret, a small endpoint for the app.

Because status: 'pending' makes Mailchimp send a confirmation email, the success message in the JSON ("Check your inbox for a confirmation email") is accurate. If you subscribe people directly, change successMessage.

Other changes to the form

  • Validation rule: domain/waitlist/use_cases/validate_email.dart. It is deliberately lenient (one @, no spaces, a dot in the domain). Tests are in test/domain_test.dart.
  • Extra fields (name, company): add a field to _Fields in waitlist_form.dart, pass it through WaitlistCubit.submit, JoinWaitlist and WaitlistRepository.join, and send it from your data source.
  • Toast: the listener in waitlist_view.dart fires on success and on a service failure. Validation errors are inline only.

#Wire pricing buttons to Stripe

Each plan's button is a Link in the pricing JSON. Anything that does not start with # reaches onLink, so a checkout is a link plus a few lines to open it.

Option 1: Stripe Payment Links (no server)

  1. In the Stripe Dashboard create a Payment Link per price: Team monthly, Team yearly, Scale monthly, Scale yearly.
  2. Put them in the plans. Use the {period} token to carry the billing choice, and let your own redirect page pick the link: 
    'cta': <String, Object?>{
  'label': 'Start free trial',
  'href': 'https://acme.example/checkout?plan=team&period={period}',
},
    The page replaces {period} with monthly or yearly from the visitor's current toggle, then hands the result to onLink.
  3. Open it in onLink with url_launcher (flutter pub add url_launcher): 
    import 'package:url_launcher/url_launcher.dart';

const Map<String, String> paymentLinks = <String, String>{
  'team:monthly': 'https://buy.stripe.com/test_team_monthly',
  'team:yearly': 'https://buy.stripe.com/test_team_yearly',
  'scale:monthly': 'https://buy.stripe.com/test_scale_monthly',
  'scale:yearly': 'https://buy.stripe.com/test_scale_yearly',
};

Future<void> handleLink(String href) async {
  final Uri uri = Uri.parse(href);

  if (uri.host == 'acme.example' && uri.path == '/checkout') {
    final String? link =
        paymentLinks['${uri.queryParameters['plan']}:${uri.queryParameters['period']}'];
    if (link != null) await launchUrl(Uri.parse(link), webOnlyWindowName: '_self');
    return;
  }
  if (const <String>['http', 'https', 'mailto'].contains(uri.scheme)) {
    await launchUrl(uri, webOnlyWindowName: '_self');
  }
}

// LandingApp(onLink: handleLink)

Skip the middleman if you prefer: put the Stripe URL straight in href and add a second plan per period, or write your own pricing data source (see package mode) that emits a different href per period.

Option 2: Checkout Sessions from your server

Better when you need seats, coupons or a customer record. The href is your endpoint; it creates a session and redirects:

server/checkout.js
// Node.js with stripe
app.get('/checkout', async (req, res) => {
  const prices = {
    'team:monthly': 'price_123',  'team:yearly': 'price_124',
    'scale:monthly': 'price_125', 'scale:yearly': 'price_126',
  };
  const price = prices[`${req.query.plan}:${req.query.period}`];
  if (!price) return res.status(400).send('Unknown plan');

  const session = await stripe.checkout.sessions.create({
    mode: 'subscription',
    line_items: [{ price, quantity: 1, adjustable_quantity: { enabled: true, minimum: 1 } }],
    subscription_data: { trial_period_days: 14 },
    success_url: 'https://acme.example/welcome',
    cancel_url: 'https://acme.example/#pricing',
  });
  res.redirect(303, session.url);
});

On the page, 'href': 'https://api.acme.example/checkout?plan=team&period={period}' and launchUrl(uri, webOnlyWindowName: '_self') are all it takes.

Keeping prices in one place

The numbers on the page and the numbers in Stripe must agree. The page shows monthlyPrice and a percentage discount; Stripe has real prices. Either generate the pricing JSON from your Stripe prices on the server (write a PricingRemoteDataSource that fetches it), or check them against each other in a test.

#Branding and theming

The template contains no hard-coded colours (apart from Cairn's black overlay behind sheets). Every colour, radius and text style comes from CairnTheme, so a theme change re-skins the whole page.

Colours

CairnTheme.light and CairnTheme.dark are the defaults. Override any token with copyWith:

import 'package:cairn_ui/cairn_ui.dart';
import 'package:flutter/material.dart';

const Color brand = Color(0xFF4F46E5);   // indigo

final CairnTheme light = CairnTheme.light.copyWith(
  primary: brand,
  primaryForeground: Colors.white,
  ring: brand,
);
final CairnTheme dark = CairnTheme.dark.copyWith(
  primary: const Color(0xFF818CF8),
  primaryForeground: const Color(0xFF0B0B1A),
  ring: const Color(0xFF818CF8),
);

MaterialApp(
  theme: CairnTheme.materialTheme(light),
  darkTheme: CairnTheme.materialTheme(dark),
  ...
)

What primary colours on this page: the main buttons, the logo tile, the number circles in "How it works", the checkmarks in the spotlights, the highlighted plan's ring, the tallest bar in the mockup. Change it once and all follow. Backgrounds come from background, card, muted and border; text from foreground and mutedForeground. Star ratings use Cairn's warning tone.

Fonts

Set fontFamily (and optionally fontFamilyFallback) on the theme, as in Mount it. Every text style in the template goes through theme.textStyle(...) so it picks the font up.

Radius

CairnTheme.copyWith(radius: 14) scales every corner (cards, buttons, inputs, images) together; radius: 0 gives a sharp-cornered look.

Layout constants

Max content widthLandingLayout.maxContentWidth (1120) in core/presentation/layout.dart
BreakpointsLandingLayout.breakpointFor: compact under 640, medium under 1024, expanded above
Navbar collapses into a menuLandingLayout.navCollapseWidth (1000)
Section spacingSectionFrame: 56, 80, 96 px top and bottom by breakpoint; side gutter 20 or 32
Entrance animationReveal: 500 ms (CairnMotion.d500) fade and 20 px lift, once, when first scrolled into view; skipped when the system asks for reduced motion

Dark mode

Follows MaterialApp.themeMode. To force it: themeMode: ThemeMode.dark. To give visitors a switch, hold a ValueNotifier<ThemeMode> above MaterialApp and add a button (for instance in the navbar widget) that flips it.

#Swap in-template navigation for go_router

The template keeps its own navigation so it runs in any app: LandingNavigationCubit holds intent (goTo, activate) and LandingShell performs the scroll. If your app already has a router you usually keep all of that and only connect the three seams: where non-anchor links go, which section to open on arrival, and what to do when the visible section changes.

router.dart
import 'package:cairn_template_landing/cairn_template_landing.dart';
import 'package:flutter/material.dart';
import 'package:flutter/services.dart';
import 'package:go_router/go_router.dart';
import 'package:url_launcher/url_launcher.dart';

final GoRouter router = GoRouter(
  routes: <RouteBase>[
    GoRoute(
      path: '/',
      builder: (BuildContext context, GoRouterState state) => Scaffold(
        body: LandingApp(
          // /#pricing arrives as the URL fragment.
          initialSection: state.uri.fragment.isEmpty ? null : state.uri.fragment,
          onLink: (String href) => _open(context, href),
          onSectionChanged: (String id) {
            // Optional: keep the address bar in step without adding history.
            SystemNavigator.routeInformationUpdated(
              uri: Uri(path: '/', fragment: id),
              replace: true,
            );
          },
        ),
      ),
    ),
    GoRoute(path: '/sign-in', builder: (_, __) => const SignInPage()),
    GoRoute(path: '/privacy', builder: (_, __) => const PrivacyPage()),
  ],
);

void _open(BuildContext context, String href) {
  final Uri uri = Uri.parse(href);
  if (uri.hasScheme) {
    launchUrl(uri, webOnlyWindowName: '_self');   // https:, mailto:
  } else {
    context.go(href);                             // /sign-in, /privacy, ...
  }
}

MaterialApp.router(routerConfig: router, ...)

Real routes per section (/pricing)

If you want /pricing to be a shareable URL that opens the landing page scrolled to pricing:

GoRoute(
  path: '/:section(features|how-it-works|testimonials|pricing|faq|waitlist)',
  pageBuilder: (BuildContext context, GoRouterState state) => NoTransitionPage<void>(
    key: const ValueKey<String>('landing'),     // same key: the page is reused
    child: Scaffold(
      body: LandingApp(
        initialSection: state.pathParameters['section'],
        onLink: (String href) => _open(context, href),
      ),
    ),
  ),
),

Two caveats. initialSection is applied once, when the page first builds, so navigating between /pricing and /faq inside the same page instance will not re-scroll; for that, rebuild the page (give it a ValueKey of the section) or call goTo yourself. And the 600 ms wait before scrolling assumes content loads quickly; with a slow backend raise _initialScrollDelay in landing_shell.dart.

Replacing the cubit entirely

If you want the router to own scrolling too, delete LandingNavigationCubit and in landing_shell.dart replace the BlocListener that calls _scrollTo with a listener on your router state. The sections themselves have no navigation dependency: they only call LandingActions.of(context).open(href).

#SEO and deploy notes for Flutter web

Build

flutter build web --release
# served from a sub-path, e.g. https://example.com/kestrel/
flutter build web --release --base-href /kestrel/

--base-href must start and end with /. It rewrites <base href> in build/web/index.html; all asset URLs (including the template's images) are relative to it.

One page, so a single fallback

The page has one route, but if you use path URLs (/pricing with go_router) the server must return index.html for unknown paths:

nginx
# nginx
location / {
  try_files $uri $uri/ /index.html;
}
Firebase Hosting
// firebase.json
{
  "hosting": {
    "public": "build/web",
    "rewrites": [{ "source": "**", "destination": "/index.html" }]
  }
}
Netlify
# Netlify: web/_redirects (copied into build/web)
/*    /index.html   200

On GitHub Pages copy index.html to 404.html after building. Keep static, cacheable files (images, main.dart.js) with long cache headers; they are fingerprinted by Flutter's service worker.

Meta tags

Search and social previews read your static web/index.html, not the Flutter canvas. Edit the <head>:

web/index.html
<title>Kestrel: plan work your whole team can see</title>
<meta name="description" content="Kestrel brings roadmaps, tasks and reporting into one calm workspace.">
<link rel="canonical" href="https://kestrel.example/">

<meta property="og:type" content="website">
<meta property="og:title" content="Kestrel: plan work your whole team can see">
<meta property="og:description" content="Roadmaps, tasks and reporting in one calm workspace.">
<meta property="og:image" content="https://kestrel.example/og.png">   <!-- 1200x630 -->
<meta property="og:url" content="https://kestrel.example/">
<meta name="twitter:card" content="summary_large_image">

<meta name="theme-color" content="#ffffff" media="(prefers-color-scheme: light)">
<meta name="theme-color" content="#0a0a0a" media="(prefers-color-scheme: dark)">
<link rel="icon" href="favicon.png">

Social crawlers do not run JavaScript, so the og:image must be a normal absolute URL to a file you host.

Crawlability, honestly

A Flutter web app draws to a canvas. Google can index some Flutter pages, but you should not rely on it for a marketing site. If organic search matters:

  • Put a short, real HTML description in web/index.html inside <noscript> (and in a visually hidden element), including the headline, the main features and the pricing in text.
  • Consider a plain-HTML landing page on the root domain and this Flutter page as the app's own marketing view, or pre-render with a service.
  • Keep a sitemap.xml and robots.txt in web/.

The widgets expose proper semantics (headings, buttons, labelled rating and progress) so assistive technology works; call SemanticsBinding.instance.ensureSemantics() in main() if you want the accessibility tree built from the first frame instead of when a screen reader asks.

Analytics

Add the tag in web/index.html (Google Analytics 4 shown):

web/index.html
<script async src="https://www.googletagmanager.com/gtag/js?id=G-XXXXXXXXXX"></script>
<script>
  window.dataLayer = window.dataLayer || [];
  function gtag() { dataLayer.push(arguments); }
  gtag('js', new Date());
  gtag('config', 'G-XXXXXXXXXX');
</script>

Then report events from the two callbacks the page gives you:

import 'dart:js_interop';

@JS('gtag')
external void _gtag(String command, String name, JSObject params);

void track(String name, Map<String, String> params) =>
    _gtag('event', name, params.jsify()! as JSObject);

LandingApp(
  onLink: (String href) {
    track('click', <String, String>{'href': href});
    handleLink(href);
  },
  onSectionChanged: (String id) =>
      track('section_view', <String, String>{'section': id}),
)

onLink does not fire for # anchors (the template handles those), so to count those too call track from onSectionChanged or wrap the data. For a waitlist conversion, track in your data source after a successful submit.

If you use cookies or similar, add your consent banner before loading the tag.

Performance

  • Use the default renderer settings of your Flutter version; the page has no heavy effects. Images are the main weight: about 560 KB for the bundled nine.
  • The page builds every section up front (it is one scroll), which is fine at this size.
  • Defer non-critical scripts, and serve images through a CDN.

Rules for widget tests here

  • Never pumpAndSettle. Cairn has repeating animations (spinners, indeterminate progress), so the tree never settles and the call times out. Pump fixed durations; test/support/pump_landing.dart has a settle(tester, milliseconds) helper.
  • AnimatedSwitcher keeps the old child for its duration. After changing the billing period, pump about 600 ms before expecting the old price to be gone.
  • Let toasts expire. A CairnToast has a four-second timer; pump past it (settle(tester, 5000)) at the end of the test or Flutter reports a pending timer.
  • Load a real font. Flutter's default test font (Ahem) has square glyphs that are much wider than real text, which creates overflows that never happen on a device. The helper loads Geist from the repository's fonts/ folder when it can find it; point it at your own font file if you copy the template.
  • Set the viewport. tester.view.physicalSize = Size(390, 900); tester.view.devicePixelRatio = 1; and reset it with addTearDown(tester.view.reset).
  • Scroll before tapping: tester.ensureVisible(finder) stops at the edge, which can be under the sticky navbar. The tests scroll a further 250 px back.

#Troubleshooting and FAQ

Images do not show (copy mode)
Set LandingPackage.name to null and declare assets/images/ in your pubspec. In package mode, paths resolve as packages/cairn_template_landing/...; a typo shows a muted box instead of an error.
Icons are rectangles or missing in release or in tests
The page uses Material icons: keep uses-material-design: true. In widget tests, load the MaterialIcons font if you take screenshots; assertions do not need it.
FormatException: Expected a string at "headline", got null
The content JSON is missing or mistypes a required key. The message names the key; compare with the JSON reference. The error appears in the section's cubit as a failed load and the section shows a "Could not load this section. Retry" button.
A navbar link does nothing
The href must be # plus an id from SectionIds.all, and that id must be wrapped with keyed(...) in landing_page.dart. Other hrefs go to onLink, which does nothing if you did not pass one.
The page scrolls but the highlighted link is one behind
A section counts as active once its top is within 120 px of the top of the page. Change _activationOffset in landing_shell.dart. The last sections (waitlist, footer) may never reach the top because the page ends first.
Menu sheet or toast does not appear
The sheet needs a Navigator above the page (use MaterialApp); the toast needs the page's own CairnToaster, which LandingShell provides. If you wrap LandingApp in something that clips or hides overlays, the toast can be clipped.
Overflow errors on a phone
Long unbroken strings (an email address in a title, a very long headline word) can overflow. All copy wraps, but a single word wider than the screen cannot. Shorten it, or set a smaller size in the view.
pumpAndSettle timed out in my tests
See Testing: Cairn has repeating animations. Pump fixed durations.
"A Timer is still pending" at the end of a test
A toast timer (4 s) or the demo signup delay is still running. Pump past it, or register a zero-latency data source: InMemoryWaitlistRemoteDataSource(latency: Duration.zero).
"No LandingScope above this context"
A widget from the template was built outside LandingApp. Only LandingApp creates the container; mount that, not individual views.
Can I use only some sections?
Yes: remove the others from LandingPage (copy mode). Sections are independent; only the navbar and footer depend on the site info.
Can I add a language switch?
Write a data source per language and swap it with overrides (rebuild the page with a different Key when the language changes). All visible text except a few accessibility labels ("Open menu", "Billing", error messages in ValidateEmail) comes from the data.
Why does the page reload content when I rotate the phone?
It should not: content is held by cubits owned by each section's view model. If a parent rebuilds LandingApp with a new key, everything starts over by design.
How do I make the hero a split layout with the text on the left?
Edit presentation/hero/views/hero_view.dart: replace the centred Column with a Row of the copy and the mockup at viewport.isExpanded. The content model does not change.
