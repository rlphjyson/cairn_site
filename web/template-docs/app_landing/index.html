App landing page template

A one-page site that sells a phone app, built only from cairn_ui. This guide takes you from copy it in to shipping it for your own app.

Overview & architecture

The template is a Flutter package, cairn_template_app_landing, that exposes one widget: AppLandingApp. The demo app it promotes is invented: Ember, a habit coach. It has eleven sections in one scroll, under a sticky navbar whose links smooth-scroll and highlight the section in view (below 1000 px they move into a menu sheet):

IdSectionBuilt from
heroHeadline, App Store and Google Play buttons, rating line, two overlapping live phonesCairnMockupPhone, CairnButton, CairnRating, CairnAvatarGroup
trustPress mentions as text wordmarks, award badgestext and Cairn tokens
featuresFour tabs, each switching the phone screen beside the copyCairnTabs, CairnMockupPhone
how-it-worksThree numbered stepsCairnCard
galleryFive phone frames with captionsCairnCarousel
statsA photo and four figuresCairnStats
reviewsRating summary, one bar per star count, review cards, a “Write a review” toastCairnCard, CairnProgress, CairnRating, CairnAvatar, CairnToast

It is organised as clean architecture by layer, then by feature, with flutter_bloc for state and get_it for dependency injection. Nothing is generated.

lib/
├─ app_landing_app.dart            entry widget (AppLandingApp)
├─ core/
│  ├─ infrastructure/di/           get_it registration
│  └─ presentation/                navigation cubit, live phone screens, shared widgets
├─ common/                         section ids, content keys, formatting, JSON reader
├─ data/
│  ├─ content/remote/              AppContentDataSource + the demo JSON
│  ├─ download/remote/             DownloadLinkService + in-memory stand-in
│  └─ <feature>/repositories/      implement the domain interfaces
├─ domain/<feature>/               models, mappers, repository interfaces, use cases
└─ presentation/<feature>/         bloc, view models, views, widgets (+ shell/)
The one rule to remember

Dependencies point inwards: presentation → domain ← data. To change where the copy or the download link goes you touch data/ (or pass a parameter). To change how a section looks you touch presentation/.

The logic worth testing is pure, in domain/: GetFeatures, GetReviews with RatingDistribution, CalculatePrice, ValidateContact, SendDownloadLink and BuildQrPattern.

Install

A. As a package (recommended)

# pubspec.yaml
dependencies:
  cairn_ui: ^0.2.0
  cairn_template_app_landing:
    git:
      url: https://github.com/rlphjyson/cairn_site.git
      path: templates/app_landing
      ref: main            # pin a tag or commit for production

Or, from a local checkout: path: ../cairn_site/templates/app_landing.

B. Copy the source into your app

  1. Copy templates/app_landing/lib/ into lib/landing/ and assets/images/ into your app’s assets/images/.
  2. Add cairn_ui, flutter_bloc, get_it and equatable to your pubspec.yaml, and declare assets/images/.
  3. In lib/common/constants/app_landing_package.dart set AppLandingPackage.name to null, so images resolve from your app instead of the package.
  4. Rewrite the package:cairn_template_app_landing/… imports to your app’s package name. Files inside the template use relative imports, so only your own references change.
Photographs

The eight JPEGs in assets/images/ (six reviewer portraits and two lifestyle photos, about 560 KB together) are from Pexels; see NOTICE.md. Replace them with your own and update the file names in the JSON (avatar, photo) and in presentation/download/views/download_view.dart (DownloadView.photo).

Mount it

The template reads colours, radii and type from CairnTheme, so the host app must provide one. Here is a complete main.dart that opens the store listings and the other links with url_launcher:

import 'package:cairn_template_app_landing/cairn_template_app_landing.dart';
import 'package:cairn_ui/cairn_ui.dart';
import 'package:flutter/material.dart';
import 'package:url_launcher/url_launcher.dart';

void main() => runApp(const MyApp());

class MyApp extends StatelessWidget {
  const MyApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      title: 'Ember: build habits that stick',
      debugShowCheckedModeBanner: false,
      theme: CairnTheme.materialTheme(CairnTheme.light),
      darkTheme: CairnTheme.materialTheme(CairnTheme.dark),
      home: Scaffold(
        body: AppLandingApp(
          // The two store buttons.
          onStoreTap: (StoreKind store, String href) =>
              launchUrl(Uri.parse(href), webOnlyWindowName: '_blank'),
          // Pricing buttons, footer links... anything that is not a #anchor.
          onCtaTap: (String href) => launchUrl(Uri.parse(href)),
        ),
      ),
    );
  }
}

AppLandingApp fills whatever space its parent gives it and adapts to that width (not the screen’s), so put it in a Scaffold body, an Expanded or a fixed-height box. Each instance creates its own dependency container and disposes it, so two pages never share state. All parameters are optional:

ParameterTypeDoes
contentDataSourceAppContentDataSource?Where every word of copy comes from; defaults to the in-memory demo
linkServiceDownloadLinkService?Sends the download link by SMS or email; defaults to a stand-in
onStoreTapvoid Function(StoreKind, String)?A store button was pressed; gets StoreKind.appStore or StoreKind.googlePlay and the URL from the content
onCtaTapValueChanged<String>?Any other link that is not a # anchor (pricing buttons, footer links, a navbar button that points away)
initialSectionString?Scroll to a section id shortly after the first build (see SectionIds)
onSectionChangedValueChanged<String>?The section at the top of the viewport changed
overridesvoid Function(GetIt)?Swap any other registration before the page builds

Links in the content that start with # scroll to that section; everything else goes to onCtaTap. Until you pass the callbacks, the buttons do nothing outward, so a store button without onStoreTap is inert, on purpose.

Change the app name, tagline, copy and store links

Everything on the page, including the screens inside the phones, is one JSON-shaped document in lib/data/content/remote/app_content_json.dart. Each top-level key is one ContentSections entry. The name, the tagline and the store links are in the first one, _site:

const JsonMap _site = <String, Object?>{
  'brandName': 'Ember',
  'brandIcon': 'fire',                  // a name from AppLandingIcons
  'tagline': 'Build habits that stick, one small win at a time.',
  'navLinks': <Object?>[
    <String, Object?>{'label': 'Features', 'href': '#features'},
    // ...
  ],
  'cta': <String, Object?>{'label': 'Get the app', 'href': '#download'},
  'appStore': <String, Object?>{
    'caption': 'Download on the',
    'label': 'App Store',
    'icon': 'apple',                    // a generic phone glyph, not a logo
    'href': 'https://apps.apple.com/app/id0000000000',
  },
  'googlePlay': <String, Object?>{
    'caption': 'Get it on',
    'label': 'Google Play',
    'icon': 'play',
    'href': 'https://play.google.com/store/apps/details?id=com.example.ember',
  },
};

The navbar, the hero, the download section and the footer all read this one object (through the session ContentCubit<SiteInfo>), so the app is named in exactly one place. The store buttons are ordinary CairnButtons with a Material glyph and a two-line label; no store logos are used. If your store guidelines require the official badges, replace StoreButton in core/presentation/widgets/store_buttons.dart with an Image.asset of the badge inside a CairnLink.

A missing or mistyped key throws a FormatException that names it, so a typo fails loudly instead of rendering a blank. Icon names (fire, bell, award…) are resolved by core/presentation/app_landing_icons.dart; add one there to use it anywhere. Unknown names fall back to a dot.

Serve the content from somewhere else

The page only knows AppContentDataSource, which has one method. Implement it with a CMS, an API or a bundled JSON file and pass it in:

class AssetContent implements AppContentDataSource {
  const AssetContent(this.locale);
  final String locale;

  @override
  Future<JsonMap> fetchSection(String section) async {
    final String text = await rootBundle.loadString('assets/content/$locale.json');
    final Map<String, Object?> all = jsonDecode(text) as Map<String, Object?>;
    return (all[section]! as Map).cast<String, Object?>();
  }
}

AppLandingApp(contentDataSource: const AssetContent('en'))

section is one of the ContentSections constants: site, hero, trust, features, howItWorks, gallery, stats, reviews, pricing, faq, download, footer.

Colours and type

Everything resolves through CairnTheme; there are no hard-coded colours (the only fixed colours are the dark gradient and the white caption over the photograph in the stats section). Brand it where you build the theme:

final CairnTheme brand = CairnTheme.light.copyWith(
  primary: const Color(0xFFE8590C),
  primaryForeground: const Color(0xFFFFFFFF),
  radius: 12,            // every corner rescales from this one number
  fontFamily: 'Inter',
);
MaterialApp(theme: CairnTheme.materialTheme(brand), ...);

The phones, the avatars’ rings, the progress bars and the store buttons all follow the theme, in light and dark.

Reorder, add or remove a section

Edit the list in presentation/shell/app_landing_page.dart and the matching id in common/constants/section_ids.dart (SectionIds.all is the order the navbar uses to work out which section is active). A section with no navLinks entry is simply not in the navbar.

Edit features and the live phone screens

The phones are not screenshots. Each one is a real Cairn UI, laid out once at 260 × 587 logical pixels and scaled into a CairnMockupPhone, so it is sharp at any size, follows light and dark, and cannot overflow. Five kinds exist (ScreenKind): today, progress, calendar, settings and goals. The hero uses two of them, the features section four and the gallery five, all defined once in the JSON file (_todayScreen, _progressScreen, _calendarScreen, _settingsScreen, _goalsScreen) and referenced by name.

Screen JSON

FieldUsed byMeaning
kindalltoday | progress | calendar | settings | goals
title, subtitleallThe large title and the line under it
descriptionallWhat a screen reader announces for the phone (required)
taballWhich of the four dock tabs is highlighted, 0 to 3

Change a value and the phone changes: set a habit’s done to true and the ring on the Today screen fills (it is computed from the rows).

Build a new mock screen from Cairn widgets

Say you want a Streak Freeze screen.

  1. Add a value to ScreenKind in domain/shared/models/app_screen.dart (freeze). The mapper matches the JSON kind against the enum names, so nothing else changes there.
  2. Write the body in core/presentation/mock/app_screen_view.dart. The helpers _Bordered, _Row, _IconTile, _Title and _Caption are sized for the phone; combine them with any Cairn widget (CairnProgress, CairnRadialProgress, CairnBadge, CairnButton…).
  3. Add a case to the switch (screen.kind) in AppScreenView.build. The compiler tells you if you forget: the switch is exhaustive.
  4. Add a map with 'kind': 'freeze' to the JSON file and reference it from a feature ('screen': _freezeScreen) or a gallery slide.
// core/presentation/mock/app_screen_view.dart
class _FreezeBody extends StatelessWidget {
  const _FreezeBody({required this.screen});

  final AppScreen screen;

  @override
  Widget build(BuildContext context) {
    return Column(
      crossAxisAlignment: CrossAxisAlignment.stretch,
      children: <Widget>[
        _Bordered(
          children: <Widget>[
            for (final ScreenItem item in screen.items)
              _Row(
                leading: _IconTile(item.icon, active: item.done),
                title: item.label,
                detail: item.detail,
                trailing: CairnBadge(
                  variant: CairnBadgeVariant.secondary,
                  label: Text(screen.badge),
                ),
              ),
          ],
        ),
        const Spacer(),
        CairnButton(expand: true, onPressed: () {}, child: Text(screen.headline)),
        const SizedBox(height: 10),
      ],
    );
  }
}

// ... and in AppScreenView.build:
ScreenKind.freeze => _FreezeBody(screen: screen),
Keep the design size

Lay the body out for a 228 px wide column (the 260 px design width minus 16 px padding each side). Whatever fits there fits every phone, because the whole screen is scaled as one picture. MockPhone excludes it from focus, pointer input and the semantics tree and describes it with description instead, so interactive Cairn widgets inside it are safe.

Use a real screenshot instead

Replace MockPhone where you need a photograph of your app: CairnMockupPhone(child: Image.asset('assets/shots/today.png', fit: BoxFit.cover)). The hero, the features and the gallery each build their phone in one place (hero_phones.dart, features_view.dart, gallery_view.dart). Give the image a semanticLabel.

Reviews and rating data

You supply five numbers; the page derives everything else. That is deliberate: the average, the total, the width of every bar and the line “120K ratings” cannot disagree.

const JsonMap _reviews = <String, Object?>{
  'eyebrow': 'Reviews',
  'title': 'Rated 4.8 by people who stuck with it',
  'subtitle': 'Real words from the App Store and Google Play.',
  // How many people gave each star count. Total, average and bars are derived.
  'distribution': <String, Object?>{
    '5': 103200, '4': 10800, '3': 3000, '2': 1200, '1': 1800,
  },
  'reviews': <Object?>[
    <String, Object?>{
      'id': 'r1',
      'title': 'My 200 day streak says it all',
      'body': 'I have tried every habit app...',
      'author': 'Priya S.',
      'date': '2026-09-28',               // ISO 8601
      'rating': 5,                          // 1 to 5
      'avatar': 'assets/images/avatar-priya.jpg',   // optional: initials if absent
    },
  ],
  'writeReview': <String, Object?>{
    'label': 'Write a review',
    'toastTitle': 'Thanks for sharing',
    'toastMessage': 'Reviews are written in the app...',
  },
};
  • RatingDistribution (domain/reviews/models/reviews_content.dart) exposes total, average, averageLabel (4.8), countFor(star) and shareFor(star). The five rows of CairnProgress use shareFor.
  • GetReviews sorts the cards newest first, so the JSON can be in any order.
  • The hero’s rating and ratingText are separate strings. Keep them in step with the distribution (a test in domain_test.dart fails if the demo content drifts; add the same check for your numbers).
  • “Write a review” shows a CairnToast. Stores only accept reviews from people who installed the app, so the demo points to the app. To link straight to the store’s review page instead, change the button in presentation/reviews/views/reviews_view.dart to call AppLandingActions.of(context).openStore(StoreKind.appStore, href).
Do not invent reviews for a real app

The demo reviews are fictional. For a real product show real, attributed reviews, and consider the consumer-protection rules in your market on testimonials and ratings.

Pricing

Two plans in _pricing. monthlyPrice is the list price per month (0 is free, absent means “Custom”); yearlyDiscountPercent is taken off for yearly billing. CalculatePrice rounds to the cent: at 6.99 and 40% the yearly price is $4.19 a month, billed $50.28 a year, saving $33.60. A plan’s button href may contain {period}, which becomes monthly or yearly before it reaches onCtaTap:

'cta': <String, Object?>{
  'label': 'Start free trial',
  'href': 'https://ember.example/trial?plan=premium&period={period}',
},

Both the “Monthly”/“Yearly” labels and the switch toggle the same state. Store subscriptions are normally bought inside the app, so a link like this usually opens the store or your own checkout; payments are not part of this template.

Replace the demo QR

The card draws a QR-looking pattern (BuildQrPattern seeds it from qr.payload; QrPainter paints it) and labels itself as a demo. It will not scan. Before launch, encode your smart link for real. With qr_flutter:

// presentation/download/widgets/qr_card.dart: replace the CustomPaint
// (and drop the Demo badge and note) with:
import 'package:qr_flutter/qr_flutter.dart';

SizedBox.square(
  dimension: 152,
  child: QrImageView(
    data: content.payload,            // e.g. https://ember.example/get
    backgroundColor: theme.card,
    eyeStyle: QrEyeStyle(color: theme.foreground),
    dataModuleStyle: QrDataModuleStyle(color: theme.foreground),
  ),
)

Or generate the code once (PNG or SVG) and show it with Image.asset. Two rules for scannable codes: keep a light background behind a dark code (in dark mode use a fixed white tile instead of theme.card), and point it at one smart link on your own domain that redirects by platform (see Smart banners and deep links), so printed codes survive a store change.

Wire “send me the link” to SMS and email

The form accepts an email address or a phone number. ValidateContact checks it (an email has one @ and a dotted domain; a phone has 7 to 15 digits with an optional +), SendDownloadLink runs the validation and calls the repository, and the repository calls your DownloadLinkService:

abstract interface class DownloadLinkService {
  Future<void> send(Contact contact);   // throws DownloadLinkException
}

class Contact {            // Contact(ContactKind.email | ContactKind.phone, value)
  final ContactKind kind;
  final String value;      // emails trimmed; phones as digits with a leading + if typed
}

The default InMemoryDownloadLinkService waits 700 ms and accepts everything except addresses ending @fail.example and numbers ending 0000, so you can see the error state. Throw DownloadLinkException(message) with a sentence a visitor can read; any other exception becomes a generic message.

Never put provider keys in the app

A Flutter web bundle is public. SMS and email providers must be called from your backend, which also rate-limits and keeps abuse (SMS pumping) in check. The service below only talks to your own endpoint.

// lib/data/download/http_download_link_service.dart
import 'dart:convert';

import 'package:cairn_template_app_landing/cairn_template_app_landing.dart';
import 'package:http/http.dart' as http;

class HttpDownloadLinkService implements DownloadLinkService {
  HttpDownloadLinkService(this._client, {required this.endpoint});

  final http.Client _client;
  final Uri endpoint;

  @override
  Future<void> send(Contact contact) async {
    final http.Response res = await _client.post(
      endpoint,
      headers: <String, String>{'Content-Type': 'application/json'},
      body: jsonEncode(<String, String>{
        'channel': contact.kind.name,      // 'email' or 'phone'
        'to': contact.value,
      }),
    );
    if (res.statusCode == 202) return;
    if (res.statusCode == 429) {
      throw const DownloadLinkException(
        'Too many requests. Please try again in a minute.',
      );
    }
    if (res.statusCode == 422) {
      throw const DownloadLinkException(
        'We could not use that address. Please check it and try again.',
      );
    }
    throw const DownloadLinkException(
      'We could not send the link right now. Please try again in a moment.',
    );
  }
}

// main.dart
AppLandingApp(
  linkService: HttpDownloadLinkService(
    http.Client(),
    endpoint: Uri.parse('https://api.example.com/download-link'),
  ),
)

SMS with Twilio (backend)

An endpoint for the service above, in Node with Express and Twilio’s helper library. The phone arrives with only digits (and a + if the visitor typed one), so the backend decides the country: parse with libphonenumber-js and a default region, and reject anything that is not a valid mobile number.

import express from 'express';
import rateLimit from 'express-rate-limit';
import twilio from 'twilio';
import { parsePhoneNumberFromString } from 'libphonenumber-js';

const client = twilio(process.env.TWILIO_ACCOUNT_SID, process.env.TWILIO_AUTH_TOKEN);
const app = express();
app.use(express.json());

const limiter = rateLimit({ windowMs: 60_000, limit: 3 });   // per IP

app.post('/download-link', limiter, async (req, res) => {
  const { channel, to } = req.body ?? {};
  const link = 'https://ember.example/get?utm_source=landing&utm_medium=sms';

  if (channel === 'phone') {
    const phone = parsePhoneNumberFromString(String(to), 'US');   // default region
    if (!phone?.isValid()) return res.status(422).end();
    await client.messages.create({
      to: phone.number,                     // E.164
      from: process.env.TWILIO_FROM,        // your number or messaging service
      body: `Get Ember: ${link}`,
    });
    return res.status(202).end();
  }
  if (channel === 'email') return sendEmail(String(to), link, res);
  return res.status(422).end();
});

Check your SMS provider’s rules on consent and sender registration (for example 10DLC in the US) and keep the message to a single link, which is what the form’s privacy note promises.

Email over a REST endpoint

Most transactional email providers expose a REST call. Keep it on the same backend route:

async function sendEmail(to, link, res) {
  const r = await fetch('https://api.mail-provider.example/v1/messages', {
    method: 'POST',
    headers: {
      Authorization: `Bearer ${process.env.MAIL_API_KEY}`,
      'Content-Type': 'application/json',
    },
    body: JSON.stringify({
      from: 'Ember <hello@ember.example>',
      to: [to],
      subject: 'Your Ember download link',
      text: `Here is your link: ${link}\n\nYou will not hear from us again unless you sign up.`,
    }),
  });
  return res.status(r.ok ? 202 : 502).end();
}

If you would rather skip the backend for email, a no-code form endpoint works the same way: implement DownloadLinkService with a POST to it and map its status codes to DownloadLinkExceptions. The visitor-facing states (sending spinner, inline error, success panel, toast) are all driven by the cubit and need no changes.

Smart app banners and deep links

These live in the host app’s web/ folder, not in the template.

iOS smart app banner

Safari on iPhone shows a native banner when web/index.html has this tag in <head>:

<meta name="apple-itunes-app"
      content="app-id=0000000000, app-argument=https://ember.example/get">

Android

Chrome’s install prompt reads the web manifest. To point it at your Play listing, add to web/manifest.json:

"prefer_related_applications": true,
"related_applications": [
  { "platform": "play", "id": "com.example.ember",
    "url": "https://play.google.com/store/apps/details?id=com.example.ember" }
]

Universal Links and App Links

So that your smart link opens the app when it is installed and the store when it is not, host both association files on your domain:

PlatformFileNotes
iOS/.well-known/apple-app-site-associationJSON, no extension, application/json; lists your team id and bundle id and the paths (/get*)
Android/.well-known/assetlinks.jsonLists your package name and the SHA-256 of your signing certificate

Then make https://ember.example/get a tiny server route that redirects by user agent (iPhone to the App Store, Android to Google Play, everything else back to the landing page). Use that one URL as the QR payload, in the SMS and in the emails.

One button that picks the right store

On a phone you may want a single primary button. Decide in onStoreTap or build your own button with defaultTargetPlatform:

import 'package:flutter/foundation.dart';

StoreKind preferredStore() => switch (defaultTargetPlatform) {
  TargetPlatform.android => StoreKind.googlePlay,
  _ => StoreKind.appStore,
};

Analytics and attribution links

The page reports what matters through callbacks; it ships no analytics SDK. Wire them to yours:

AppLandingApp(
  onSectionChanged: (String id) => analytics.log('section_view', {'id': id}),
  onStoreTap: (StoreKind store, String href) {
    analytics.log('store_tap', {'store': store.name});
    launchUrl(withCampaign(store, Uri.parse(href)));
  },
  onCtaTap: (String href) => analytics.log('cta_tap', {'href': href}),
)

Attribution happens in the store link. App Store Connect uses a provider token and campaign token; Google Play passes a referrer string through to the install:

Uri withCampaign(StoreKind store, Uri base, {String campaign = 'landing'}) {
  final Map<String, String> q = <String, String>{...base.queryParameters};
  switch (store) {
    case StoreKind.appStore:
      q['pt'] = '123456';          // your provider token
      q['ct'] = campaign;          // campaign token
      q['mt'] = '8';
    case StoreKind.googlePlay:
      q['referrer'] =
          'utm_source=landing&utm_medium=web&utm_campaign=$campaign';
  }
  return base.replace(queryParameters: q);
}

If you use a smart-link service or your own redirect (previous section), add the UTM parameters to the JSON hrefs instead and keep onStoreTap a plain launcher. Remember that analytics on a page that collects an email or phone number may need consent under your local privacy rules.

SEO notes for Flutter web

Be realistic

A Flutter web app paints to a canvas. Search engines and link-preview bots read the HTML your server sends, and for a Flutter app that is almost empty. This template is excellent for a product microsite, a campaign page or an internal demo; it is not the best choice when organic search is the main channel.

What you can do inside Flutter web:

  • Fill in web/index.html: <title>, <meta name="description">, canonical link, Open Graph and Twitter card tags (with a 1200 × 630 image) so shared links preview well. These are static, so one page equals one set of tags.
  • Add <noscript> or a visually hidden fallback with the headline, the pitch and the store links, and a sitemap.xml and robots.txt.
  • Add SoftwareApplication JSON-LD (name, operating system, rating, offers) to web/index.html. The rating must match your stores.
  • Keep the headings: the template marks titles with Semantics(header: true), and the semantics tree is built for assistive technology (it can be enabled for crawlers that understand it, but do not depend on it).
  • Serve the build with real status codes and fast first paint: flutter build web --release, CDN, compression.

When to pick a server-rendered page instead: if the page must rank, needs one URL per section with its own title and description, must be readable with JavaScript off, or must load instantly on slow phones, render it on the server. This repository has a worked example of that approach for a storefront, templates/jaspr_store, built with Jaspr (Dart rendered to HTML). The copy in app_content_json.dart is plain data, so you can reuse it as the source for a server-rendered version and keep this Flutter page for in-app promotion and demos.

Use go_router

The page has its own scroll navigation (AppLandingNavigationCubit) so it runs in any app. If you want a URL per section, keep the page mounted once and let the URL follow the scroll without navigating, so the page state survives:

final GoRouter router = GoRouter(
  routes: <RouteBase>[
    GoRoute(
      path: '/',
      builder: (_, GoRouterState s) => const LandingScreen(),
      routes: <RouteBase>[
        GoRoute(
          path: ':section',                       // /pricing, /faq, ...
          builder: (_, GoRouterState s) =>
              LandingScreen(section: s.pathParameters['section']),
        ),
      ],
    ),
  ],
);

class LandingScreen extends StatelessWidget {
  const LandingScreen({super.key, this.section});
  final String? section;

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      body: AppLandingApp(
        initialSection: section,                   // deep link: scroll there
        onSectionChanged: (String id) => SystemNavigator.routeInformationUpdated(
          uri: Uri.parse(id == SectionIds.hero ? '/' : '/$id'),
          replace: true,                           // update the URL, do not navigate
        ),
        onCtaTap: (String href) => launchUrl(Uri.parse(href)),
      ),
    );
  }
}

SectionIds and ContentSections are exported from the barrel, so you can build the paths from the same ids the navbar uses.

Localisation

Because every word of content comes through AppContentDataSource, localising the page is mostly a data job: pick the data source by locale (see the AssetContent example), and give each locale its own JSON with its own store URLs.

A short list of strings lives in the widgets rather than the JSON. Move them to AppLocalizations (or any intl setup) when you ship a second language:

The previous and next buttons of the carousel (Previous slide, Next slide) are cairn_ui’s own labels. For right-to-left languages wrap the page in a Directionality; layouts use start/end alignment where it matters, but check the phone mockups: a scaled screen is laid out in the ambient direction.

Responsive and accessible

WidthBehaviour
≥ 1024Two-column hero, features and download; all six navbar links; reviews summary beside two columns of cards; the carousel shows about three phones
1000–1023Navbar links still shown; single-column sections
< 1000Navbar links move into a menu sheet (the button keeps “Get the app”)

< 640One column, feature tabs without icons (and horizontally scrollable if needed), one phone per carousel page, the form stacks its button

Layout follows the width the page is given, not the screen. Accessibility details worth knowing:

  • Every control is a real Cairn control: focus rings, arrow-key navigation in the tabs, and previous/next buttons on the carousel (it also drags with touch, mouse and trackpad).
  • The mock phones are described by one sentence each and skipped by focus; the live counter under the carousel (2 of 5: Check in) is a live region, as are the form errors and the success panel.
  • The page honours the platform’s reduced-motion setting: entrance animations (Reveal, the hero phones) and smooth scrolling are skipped. Nothing loops.
  • Press names and awards are text wordmarks with a spoken label; avatars are decorative.

Testing

cd templates/app_landing
flutter pub get
dart format .
flutter analyze --fatal-infos --fatal-warnings
flutter test

The suite has three layers: domain (pricing, rating maths, contact validation, the send use case, the QR pattern, mappers), session (cubits through the real container, no widgets) and widget tests that mount AppLandingApp at 390, 768 and 1280 px in light and dark. They drive the navbar, the feature tabs, the carousel, the pricing toggle, the FAQ, the send-link form (invalid, valid, refused), the phone menu and the host callbacks, and fail on any layout overflow. Use small tester.pump(Duration) steps, never pumpAndSettle: Cairn has repeating animations (spinners), so it would never return.

// test a real backend wiring without a network
await pumpAppLanding(
  tester,
  linkService: InMemoryDownloadLinkService(latency: Duration.zero),
  onStoreTap: (StoreKind s, String href) => taps.add((s, href)),
);

When you replace a data source, keep the in-memory one for tests and register it in a test container with createAppLandingLocator(contentDataSource: ..., linkService: ...).

Migration notes

When you…Do this
Upgrade cairn_ui to a new minorBump the constraint, run flutter analyze. Components added in a minor do not break this template; read the library’s CHANGELOG for renames.
Move from copied source to the packageDelete your copy, add the dependency, restore AppLandingPackage.name, change imports back to package:cairn_template_app_landing/… and move your edits (nearly always only app_content_json.dart and your link service) into your own wrapper and data sources.
Pull template updates into a copyDiff templates/app_landing/lib between your last sync tag and the new one; because dependencies point inwards, changes are almost always inside one layer.
Replace the SaaS-style landing templateSection ids differ (trust, gallery, reviews, download); update any deep links and initialSection values.
Change state managementCubits are plain streams of immutable states. Views only call vm.cubit.method() and read state, so Riverpod or Provider can replace BlocBuilder view by view.

Troubleshooting

“No AppLandingScope above this context”

You built a view or ViewModelBuilder outside AppLandingApp. Mount AppLandingApp (it provides the scope) or wrap your tree in an AppLandingScope with a locator from createAppLandingLocator().

The store buttons do nothing

Pass onStoreTap. The template deliberately has no URL-launching dependency; the host decides how to open links.

Everything is black and white and unstyled

The host app has no CairnTheme. Use CairnTheme.materialTheme(...) or add CairnTheme.light to ThemeData.extensions.

A photo is blank or an asset error appears

If you copied the source into your app, set AppLandingPackage.name to null and declare assets/images/ in your pubspec. If you use the package, nothing needs declaring.

“FormatException: Expected a string at …”

A key is missing or has the wrong type in the content JSON. The message names the key; compare with the shapes above.

“RenderFlex overflowed” in tests

Flutter’s test font is wide. Load your real font in test/flutter_test_config.dart (the template does this for Geist when it finds it) and set fontFamily on the test theme.

The page jumps to a section on load

You passed initialSection; the page waits about 600 ms for the sections to load before scrolling. Remove it for a normal visit.

The link service never finishes

The spinner shows until send completes. Put a timeout on your HTTP call (.timeout(const Duration(seconds: 10))) and throw a DownloadLinkException from the catch.

Open an issue on the cairn_site repository with the Flutter and cairn_ui versions.
