Auth template

Authentication screens for a mobile app, built only from cairn_ui. This guide takes you from copy it in to shipping it against your own backend.

Overview

The template is a Flutter package, cairn_template_auth, that exposes one widget: AuthApp. It has seven screens with their own back stack and transitions:

  • Welcome – brand mark and tagline, Continue with Google and Continue with Apple buttons, Sign in with email, Create an account and the legal links.
  • Sign in – email, password (show/hide), remember me, forgot password, inline validation, a loading state, a wrong-credentials alert and a rate limit with a text countdown.
  • Sign up – name, email, a password with a strength meter (CairnProgress plus Too short, Weak, Fair or Strong) and a live rules checklist, confirmation, terms, and an “already registered” error.
  • Forgot password – email, then Check your inbox, which is the same whether or not the account exists.
  • Verify code – a six-digit CairnInputOtp with paste, a wrong-code message, an attempts limit and a resend cooldown.
  • Reset password – a new password with the meter, a confirmation and a success state.
  • Signed in – a placeholder with avatar initials, the person’s name, sign out and a note about the onAuthenticated hook.

It is organised as clean architecture by layer, then by feature, with flutter_bloc for state and get_it for dependency injection. Nothing is generated.

lib/
├─ cairn_template_auth.dart        barrel: AuthApp and the types a host needs
├─ auth_app.dart                   entry widget
├─ core/
│  ├─ infrastructure/di/           get_it registration (auth_injection.dart)
│  └─ presentation/                navigation cubit, widgets, copy, ViewModel
├─ common/                         policy numbers, demo account, clock, ticker
├─ data/auth/                      remote data source (+ in-memory server), repository
├─ domain/<feature>/               models, mappers, repository interface, use cases
└─ presentation/<feature>/         bloc, view models, views, widgets (+ shell/)
The one rule to remember

Dependencies point inwards: presentation → domain ← data. To connect a server you write one class, AuthRemoteDataSource, and touch nothing else. To change how a screen looks you touch presentation/.

Accessibility is part of the design: fields, buttons and stand-alone links have 44 px tap areas, icon buttons have labels, an error is part of its field’s spoken name and is announced when it appears, focus rings come from Cairn, nothing overflows at 320 px or with large system text, and with the platform’s reduce-motion setting on screens swap with no animation. The layout mirrors for right-to-left languages.

Install

A. As a package (recommended)

Keeping it a package means you can pull in fixes later with a version bump.

# pubspec.yaml
dependencies:
  cairn_ui: ^0.2.0
  cairn_template_auth:
    git:
      url: https://github.com/rlphjyson/cairn_site.git
      path: templates/auth
      ref: main            # pin a tag or commit for production

Or, from a local checkout: path: ../cairn_site/templates/auth.

B. Copy the source into your app

  1. Copy templates/auth/lib/ into lib/auth/ in your app.
  2. Add cairn_ui, flutter_bloc, get_it and equatable to your pubspec.yaml.
  3. Rewrite the package:cairn_template_auth/… imports to your app’s package name (a find-and-replace). Files inside the template use relative imports, so only your own references change.
  4. Delete cairn_template_auth.dart if you do not want the barrel. The template has no assets, so AuthPackage.name only matters if you add images.

Copying is the way to go when you want to edit the views, the copy or the DI file directly. Most changes in this guide are possible without it.

Mount it

A complete main.dart that shows the template until someone signs in, then your own home screen:

import 'package:cairn_template_auth/cairn_template_auth.dart';
import 'package:cairn_ui/cairn_ui.dart';
import 'package:flutter/material.dart';

void main() => runApp(const MyApp());

class MyApp extends StatefulWidget {
  const MyApp({super.key});

  @override
  State<MyApp> createState() => _MyAppState();
}

class _MyAppState extends State<MyApp> {
  Session? _session;

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      debugShowCheckedModeBanner: false,
      theme: CairnTheme.materialTheme(CairnTheme.light),
      darkTheme: CairnTheme.materialTheme(CairnTheme.dark),
      home: _session == null
          ? Scaffold(
              body: AuthApp(
                onAuthenticated: (Session session) =>
                    setState(() => _session = session),
                onLegalLink: (AuthLegalLink link) {
                  // Open your terms or privacy page here.
                },
                showDemoHint: true, // prints the demo account; remove in a real app
              ),
            )
          : Scaffold(
              body: SafeArea(
                child: Center(
                  child: Column(
                    mainAxisSize: MainAxisSize.min,
                    spacing: 16,
                    children: <Widget>[
                      Text('Hello, ${_session!.account.name}'),
                      CairnButton(
                        onPressed: () => setState(() => _session = null),
                        child: const Text('Sign out'),
                      ),
                    ],
                  ),
                ),
              ),
            ),
    );
  }
}

The demo

Out of the box the template talks to an in-memory server with one user, ada@example.com / Cairn-demo-1. A reset code is accepted when it is 123456. Five wrong passwords lock sign-in for 30 seconds; five wrong codes lock the code until a new one is requested.

Copy, brand and rules

Words

Every string the screens show is a member of AuthCopy (core/presentation/auth_copy.dart): titles, buttons, placeholders, the password rules, and the message for each validation issue and each failure. Edit them to change the voice. The messages about sign-in never say whether the email or the password was wrong, and the messages about recovery never say whether an account exists; keep it that way when you rewrite them.

static const String signInTitle = 'Welcome back';

The cooldowns on screen are driven by what the server says (retryAfterSeconds), falling back to these defaults. The server must enforce its own limits; the client can only display them.

Password rules

Which rules are required lives on the enum in domain/validation/models/password_assessment.dart. To require a symbol, flip one flag:

enum PasswordRule {
  minLength(required: true),
  mixedCase(required: true),
  number(required: true),
  symbol(required: true), // was false: now the checklist says so and validation enforces it
  ...
}

To drop the case and number rules in favour of length alone (current guidance favours long passwords over composition rules), set mixedCase and number to required: false and raise minPasswordLength. The checklist, the validators and the meter all read the same enum.

Strength scoring

PasswordStrength is deliberately small: one point each for mixed case, a digit, a symbol and 12 or more characters, with common passwords capped at weak. To use a dictionary-aware estimator (zxcvbn and its ports), keep the class and its return type, and change only how the level is chosen. Everything else reads the returned PasswordAssessment:

class PasswordStrength {
  const PasswordStrength(this._estimate);

  /// Your estimator: returns 0 (guessable) to 4 (very hard to guess).
  final int Function(String password) _estimate;

  PasswordAssessment call(String password) {
    if (password.isEmpty) return PasswordAssessment.empty;
    final int score = _estimate(password);
    final bool longEnough = password.length >= AuthPolicy.minPasswordLength;
    final PasswordStrengthLevel level = !longEnough
        ? PasswordStrengthLevel.tooShort
        : score <= 1
        ? PasswordStrengthLevel.weak
        : score == 2
        ? PasswordStrengthLevel.fair
        : PasswordStrengthLevel.strong;
    return PasswordAssessment(
      level: level,
      score: longEnough ? (score + 1) / 5 : 0.2 * password.length / AuthPolicy.minPasswordLength,
      met: <PasswordRule>{
        if (longEnough) PasswordRule.minLength,
        // ...the other rules, as in the original
      },
      isCommon: score == 0,
    );
  }
}

Email and name rules

ValidateEmail checks the shape only (one @, a dotted domain, at most 254 characters) because the only real proof an address works is mailing it. ValidateName wants two characters. Both are tiny classes in domain/validation/use_cases/; change them and the unit tests tell you what moved.

Adding a field or a screen

  1. Add a value to AuthField and, if it has new messages, to ValidationIssue and AuthCopy.issue.
  2. Extend the use case (SignUp) and the cubit’s submit; pass the value to the repository and the data source.
  3. Add a LabeledInput to the view, wired like its neighbours (onChanged clears the issue, onFocusLost validates).
  4. For a new screen (a two-factor step, say): add a value to AuthScreen, a cubit, a view model, a view, one registerFactoryParam line in auth_injection.dart and one case in AuthShell._screen.

Connect a backend

Everything the template knows about a server is one interface, AuthRemoteDataSource. It takes plain arguments and returns the decoded JSON body. AuthMapper turns that into models and is the only code that knows the wire format.

// a session
{ "user": { "id": "u_1", "name": "Ada Lovelace", "email": "ada@example.com" },
  "accessToken": "opaque", "refreshToken": "opaque", "expiresIn": 3600 }

// any failure (a non-2xx body decodes to the same shape)
{ "error": { "code": "rate_limited", "retryAfterSeconds": 30 } }
{ "error": { "code": "invalid_code", "attemptsRemaining": 3 } }

Codes the mapper does not know become “Something went wrong”. A thrown Exception (a dropped socket, a timeout, a TLS error) becomes “You seem to be offline”; a body that does not have the documented shape becomes the generic failure. refreshToken and expiresIn are optional.

REST example

With package:http. It adapts status codes to the error envelope for servers that do not send one, and it keeps the access token it was given so signOut can send it:

import 'dart:convert';

import 'package:cairn_template_auth/cairn_template_auth.dart';
import 'package:http/http.dart' as http;

class RestAuthRemoteDataSource implements AuthRemoteDataSource {
  RestAuthRemoteDataSource(this._client, {required Uri baseUrl}) : _base = baseUrl;

  final http.Client _client;
  final Uri _base; // for example https://api.example.com/v1/auth/
  String? _accessToken;

  Future<Map<String, Object?>> _post(
    String path,
    Map<String, Object?> body,
  ) async {
    final http.Response response = await _client
        .post(
          _base.resolve(path),
          headers: <String, String>{
            'content-type': 'application/json',
            if (_accessToken != null) 'authorization': 'Bearer $_accessToken',
          },
          body: jsonEncode(body),
        )
        .timeout(const Duration(seconds: 15)); // a timeout becomes "offline"

    final Object? decoded =
        response.body.isEmpty ? null : jsonDecode(response.body);
    final Map<String, Object?> json =
        decoded is Map<String, Object?> ? decoded : <String, Object?>{};

    if (response.statusCode >= 400 && json['error'] == null) {
      final int? retry = int.tryParse(response.headers['retry-after'] ?? '');
      return <String, Object?>{
        'error': <String, Object?>{
          'code': switch (response.statusCode) {
            401 => 'invalid_credentials',
            409 => 'email_taken',
            410 => 'code_expired',
            429 => 'rate_limited',
            _ => 'unknown',
          },
          'retryAfterSeconds': ?retry,
        },
      };
    }
    _accessToken = json['accessToken'] as String? ?? _accessToken;
    return json;
  }

  @override
  Future<Map<String, Object?>> signIn({
    required String email,
    required String password,
    required bool remember,
  }) => _post('sign-in', <String, Object?>{
    'email': email,
    'password': password,
    'remember': remember,
  });

  @override
  Future<Map<String, Object?>> signUp({
    required String name,
    required String email,
    required String password,
  }) => _post('sign-up', <String, Object?>{
    'name': name,
    'email': email,
    'password': password,
  });

  @override
  Future<Map<String, Object?>> signInWithProvider({
    required String provider,
    required String idToken,
  }) => _post('social', <String, Object?>{
    'provider': provider,
    'idToken': idToken,
  });

  @override
  Future<Map<String, Object?>> requestPasswordReset({required String email}) =>
      _post('password/forgot', <String, Object?>{'email': email});

  @override
  Future<Map<String, Object?>> verifyCode({
    required String email,
    required String code,
  }) => _post('password/verify', <String, Object?>{'email': email, 'code': code});

  @override
  Future<Map<String, Object?>> resetPassword({
    required String resetToken,
    required String password,
  }) => _post('password/reset', <String, Object?>{
    'resetToken': resetToken,
    'password': password,
  });

  @override
  Future<Map<String, Object?>> signOut() async {
    final Map<String, Object?> result = await _post('sign-out', <String, Object?>{});
    _accessToken = null;
    return result;
  }
}
Always HTTPS

Send credentials only over TLS. Never log request bodies, and never put a password or a code in a URL: they end up in server logs and proxies.

Firebase Auth example

Firebase Auth does the hashing, rate limiting and token refresh for you, and persists the session itself, so you store nothing. Two differences matter: it emails a link (not a six-digit code) for password reset, and the access token is an ID token from getIdToken(). Use recoveryByLink: true so the screens do not ask for a code (see Deep links for opening the link):

import 'package:cairn_template_auth/cairn_template_auth.dart';
import 'package:firebase_auth/firebase_auth.dart';

class FirebaseAuthRemoteDataSource implements AuthRemoteDataSource {
  FirebaseAuthRemoteDataSource([FirebaseAuth? auth])
    : _auth = auth ?? FirebaseAuth.instance;

  final FirebaseAuth _auth;

  Future<Map<String, Object?>> _session(User user, {String? name}) async =>
      <String, Object?>{
        'user': <String, Object?>{
          'id': user.uid,
          'name': user.displayName ?? name ?? '',
          'email': user.email ?? '',
        },
        'accessToken': await user.getIdToken() ?? '',
        'expiresIn': 3600,
      };

  static Map<String, Object?> _error(String code) => <String, Object?>{
    'error': <String, Object?>{'code': code},
  };

  static String _codeFor(String firebaseCode) => switch (firebaseCode) {
    'email-already-in-use' => 'email_taken',
    'too-many-requests' => 'rate_limited',
    'invalid-credential' ||
    'wrong-password' ||
    'user-not-found' ||
    'invalid-email' ||
    'user-disabled' => 'invalid_credentials',
    'expired-action-code' || 'invalid-action-code' => 'code_expired',
    _ => 'unknown',
  };

  @override
  Future<Map<String, Object?>> signIn({
    required String email,
    required String password,
    required bool remember,
  }) async {
    try {
      final UserCredential credential = await _auth.signInWithEmailAndPassword(
        email: email,
        password: password,
      );
      return _session(credential.user!);
    } on FirebaseAuthException catch (e) {
      if (e.code == 'network-request-failed') rethrow; // shown as "offline"
      return _error(_codeFor(e.code));
    }
  }

  @override
  Future<Map<String, Object?>> signUp({
    required String name,
    required String email,
    required String password,
  }) async {
    try {
      final UserCredential credential = await _auth
          .createUserWithEmailAndPassword(email: email, password: password);
      await credential.user!.updateDisplayName(name);
      return _session(credential.user!, name: name);
    } on FirebaseAuthException catch (e) {
      if (e.code == 'network-request-failed') rethrow;
      return _error(_codeFor(e.code));
    }
  }

  @override
  Future<Map<String, Object?>> signInWithProvider({
    required String provider,
    required String idToken,
  }) async {
    try {
      // Apple also needs the raw nonce you hashed into its request.
      final AuthCredential credential = provider == 'google'
          ? GoogleAuthProvider.credential(idToken: idToken)
          : OAuthProvider('apple.com').credential(idToken: idToken); // plus rawNonce
      final UserCredential result = await _auth.signInWithCredential(credential);
      return _session(result.user!);
    } on FirebaseAuthException catch (e) {
      if (e.code == 'network-request-failed') rethrow;
      return _error(_codeFor(e.code));
    }
  }

  @override
  Future<Map<String, Object?>> requestPasswordReset({required String email}) async {
    try {
      await _auth.sendPasswordResetEmail(email: email);
    } on FirebaseAuthException catch (e) {
      // Answer the same for an unknown address. Projects with email
      // enumeration protection (the default) never throw this anyway.
      if (e.code != 'user-not-found') rethrow;
    }
    return <String, Object?>{'accepted': true};
  }

  @override
  Future<Map<String, Object?>> verifyCode({
    required String email,
    required String code,
  }) => throw UnsupportedError(
    'Firebase emails a link, not a code. Mount AuthApp(recoveryByLink: true).',
  );

  @override
  Future<Map<String, Object?>> resetPassword({
    required String resetToken, // the link's oobCode
    required String password,
  }) async {
    try {
      await _auth.confirmPasswordReset(code: resetToken, newPassword: password);
      return <String, Object?>{'ok': true};
    } on FirebaseAuthException catch (e) {
      if (e.code == 'network-request-failed') rethrow;
      return _error(_codeFor(e.code));
    }
  }

  @override
  Future<Map<String, Object?>> signOut() async {
    await _auth.signOut();
    return <String, Object?>{'ok': true};
  }
}

On launch, restore the session before mounting the template: FirebaseAuth.instance.currentUser != null means the person is already signed in, so show your home screen and skip AuthApp entirely.

Registering it

As a package, pass the data source to the widget:

AuthApp(
  authDataSource: RestAuthRemoteDataSource(
    http.Client(),
    baseUrl: Uri.parse('https://api.example.com/v1/auth/'),
  ),
  onAuthenticated: (Session session) => router.go('/home'),

As copied source, edit the one registration in core/infrastructure/di/auth_injection.dart:

// Data source. Replace it with one that calls your backend.

  () => dataSource ??

Social sign-in

The welcome screen shows Continue with Google and Continue with Apple buttons. The template ships generic Material glyphs, not the providers’ logos, because each provider’s brand guidelines require its official button. The wiring point is one function, SocialIdTokenProvider: run the provider’s SDK, return the ID token it gives you, or return null if the person cancelled. The template sends the token to your data source’s signInWithProvider, and your server verifies it with the provider (signature, audience, expiry, nonce) before creating a session. Never trust a token the client says is valid.

AuthApp(
  authDataSource: myDataSource,
  socialProviders: <SocialProvider>[
    SocialProvider.google,
    if (Platform.isIOS) SocialProvider.apple,
  ],
  onSocialSignIn: (SocialProvider provider) async {
    switch (provider) {
      case SocialProvider.google:
        return signInWithGoogle();
      case SocialProvider.apple:
        return signInWithApple();
    }
  },
)

google_sign_in

For google_sign_in 7 or newer (check the package’s changelog for your version). Initialise once at start-up, with your web client ID as serverClientId so the ID token’s audience is your backend:

import 'package:google_sign_in/google_sign_in.dart';

Future<void> initGoogle() =>
    GoogleSignIn.instance.initialize(serverClientId: 'YOUR_WEB_CLIENT_ID');

Future<String?> signInWithGoogle() async {
  try {
    final GoogleSignInAccount account = await GoogleSignIn.instance.authenticate();
    return account.authentication.idToken;
  } on GoogleSignInException catch (e) {
    if (e.code == GoogleSignInExceptionCode.canceled) return null; // not an error
    rethrow; // shown as "You seem to be offline"
  }
}

sign_in_with_apple

Apple wants a nonce: send its SHA-256 to Apple, and the raw value to your server with the token so it can check the two match. Pass the raw nonce to your data source however suits your API (a closure over the nonce you generated is simplest):

import 'dart:convert';
import 'dart:math';

import 'package:crypto/crypto.dart';
import 'package:sign_in_with_apple/sign_in_with_apple.dart';

String lastRawNonce = '';

Future<String?> signInWithApple() async {
  final Random random = Random.secure();
  lastRawNonce = base64UrlEncode(
    List<int>.generate(32, (_) => random.nextInt(256)),
  );
  final String hashed = sha256.convert(utf8.encode(lastRawNonce)).toString();
  try {
    final AuthorizationCredentialAppleID credential =
        await SignInWithApple.getAppleIDCredential(
          scopes: <AppleIDAuthorizationScopes>[
            AppleIDAuthorizationScopes.email,
            AppleIDAuthorizationScopes.fullName,
          ],
          nonce: hashed,
        );
    return credential.identityToken;
  } on SignInWithAppleAuthorizationException catch (e) {
    if (e.code == AuthorizationErrorCode.canceled) return null;
    rethrow;
  }
}
Things that bite
  • Apple returns the person’s name only the first time they authorise. Save it then.
  • The App Store requires Sign in with Apple when an iOS app offers other third-party sign-in (review guideline 4.8), unless an exception applies. Show both, or neither, on iOS.
  • Replace SocialButton (presentation/welcome/widgets/social_button.dart) with the providers’ official button widgets or assets when you ship.

Without onSocialSignIn the buttons send a placeholder token, which the in-memory server accepts and a real one rejects. Pass socialProviders: const [] to hide the section and its “or” divider.

Secure session storage

The template keeps the session in memory only, for the life of the mounted AuthApp. Closing the app signs the person out. To keep them signed in, persist one thing: the refresh token, in the platform keystore, and restore it before showing any screen.

ValueWhere it livesWhy
Passworda text controller, cleared on successnever stored, never in a cubit state, never logged
Access tokenmemory (Session.accessToken)short-lived (minutes); a new one comes from the refresh token
Refresh tokenKeychain / Keystore (Session.refreshToken)long-lived, so it needs hardware-backed storage; rotate it on every use
Reset token, one-time codememory, single usean attacker who reads it can take the account

Session leaves both tokens out of its equality and toString, so a logged or equatable-printed state never shows them. Keep that habit in your own code.

import 'package:flutter_secure_storage/flutter_secure_storage.dart';

class SessionStore {
  SessionStore([FlutterSecureStorage? storage])
    : _storage = storage ?? const FlutterSecureStorage();

  static const String _key = 'refresh_token';
  final FlutterSecureStorage _storage;

  Future<String?> read() => _storage.read(key: _key);
  Future<void> save(String token) => _storage.write(key: _key, value: token);
  Future<void> clear() => _storage.delete(key: _key);
}

Save on sign-in (only when the person ticked Remember me, which arrives as Session.remembered) and clear on sign-out. Restore at launch with a call of your own that exchanges the stored token; AuthMapper.sessionFromJson is exported so you can reuse the same mapping:

Future<void> main() async {
  WidgetsFlutterBinding.ensureInitialized();
  final SessionStore store = SessionStore();

  Session? restored;
  final String? stored = await store.read();
  if (stored != null) {
    try {
      // POST /auth/refresh with the stored token; the server rotates it.
      final Map<String, Object?> json = await api.refresh(stored);
      restored = AuthMapper.sessionFromJson(
        json,
        now: DateTime.now(),
        remembered: true,
      );
      await store.save(restored.refreshToken ?? stored);
    } on Object {
      await store.clear(); // revoked, expired or offline-at-launch policy: your call
    }
  }
  runApp(MyApp(store: store, initial: restored));
}

// In MyApp:
AuthApp(
  onAuthenticated: (Session session) {
    if (session.remembered && session.refreshToken != null) {
      store.save(session.refreshToken!);
    }
    setState(() => _session = session);
  },
  onSignedOut: store.clear,
)
  • When your own home screen signs the person out, call the server’s sign-out (revoking the refresh token) and store.clear() yourself.
  • On Android use AndroidOptions(encryptedSharedPreferences: true); on iOS choose a Keychain accessibility such as first_unlock. Exclude the storage from backups.
  • Consider gating the restore with biometrics (local_auth) for sensitive apps.
  • If a rotated refresh token is ever presented twice, treat it as theft: revoke the whole token family on the server.

Enumeration and rate limits

Do not reveal who has an account

  • Sign in answers “The email or password is not right” for an unknown email and for a wrong password alike. The in-memory server also counts failures for unknown emails, so the lockout itself reveals nothing. A real server should also spend the same time on both (hash a dummy password when the user does not exist).
  • Forgot password always says “If an account exists for …, a code is on its way”. RequestPasswordReset returns void and the screen has no way to learn more, on purpose. The server must answer identically, in about the same time, whether or not it sent mail. Wrong codes for an address that was never sent one fail like any other wrong code.
  • Sign up is the one place the template trades privacy for clarity: it tells the person the email is already registered, because most apps prefer that. If you need to hide it, have the server answer success for existing emails, and mail that address “you already have an account”; then change SignUpCubit.submit to show a “check your email” state instead of mapping emailTaken to a field error. The two approaches suit different products; pick one deliberately.

Rate limits belong on the server

  • Limit per account and per IP address, so that neither password spraying (many accounts, few guesses) nor a targeted guess run (one account, many guesses) works.
  • Prefer throttling and growing delays to a hard lock: a hard lock lets anyone lock out a victim on purpose. Add a challenge (CAPTCHA, device attestation) after repeated failures.
  • Answer with 429 and Retry-After, and let the data source turn it into rate_limited with retryAfterSeconds. The sign-in screen then disables its button and shows Try again in 29s counting down as plain text. The countdown is a finite Timer owned by the cubit and cancelled when it closes.
  • A six-digit code has a million values, so allow few guesses (the template: five) and then require a new code. Keep codes short-lived (ten minutes), single use and hashed at rest, and limit how often one can be requested. A new code resets the guess count, which the template’s resend link relies on.
  • Tell people when a reset or a new sign-in happened, by email.

Deep links for reset

Two recovery styles are supported:

  • Code (the default): the email carries a six-digit code, the person types it on the verify screen, and the server answers with a resetToken.
  • Link: the email carries a link. Mount AuthApp(recoveryByLink: true) so the confirmation says “we emailed a link” and offers no code step. When the link opens your app, mount the template with the token from it: AuthApp(resetToken: token) starts on Choose a new password, and the token goes to resetPassword as the resetToken argument (Firebase’s oobCode, or your own).

Use https links that open the app (Android App Links, iOS Universal Links: https://example.com/reset?token=…), not a custom scheme, which any app can claim. With the app_links package:

import 'dart:async';

import 'package:app_links/app_links.dart';

class AuthGate extends StatefulWidget {
  const AuthGate({super.key});

  @override
  State<AuthGate> createState() => _AuthGateState();
}

class _AuthGateState extends State<AuthGate> {
  final AppLinks _links = AppLinks();
  StreamSubscription<Uri>? _subscription;
  String? _resetToken;

  String? _tokenFrom(Uri? uri) =>
      uri != null && uri.path == '/reset' ? uri.queryParameters['token'] : null;

  @override
  void initState() {
    super.initState();
    _links.getInitialLink().then((Uri? uri) {
      if (mounted) setState(() => _resetToken = _tokenFrom(uri));
    });
    _subscription = _links.uriLinkStream.listen((Uri uri) {
      final String? token = _tokenFrom(uri);
      if (token != null) setState(() => _resetToken = token);
    });
  }

  @override
  void dispose() {
    _subscription?.cancel();
    super.dispose();
  }

  @override
  Widget build(BuildContext context) => AuthApp(
    // A new key remounts the template with the new token.
    key: ValueKey<String?>(_resetToken),
    resetToken: _resetToken,
    recoveryByLink: true,
    authDataSource: myDataSource,
    onAuthenticated: (Session session) => router.go('/home'),
  );
}
Treat the token as a password
  • Single use, short life (an hour at most), bound to one account, stored hashed on the server.
  • Do not log the URL. Do not put the token in analytics events.
  • Expired or used tokens come back as code_expired; the screen then offers Start over, which goes to Forgot your password?.
  • After a successful reset, revoke the account’s other sessions and refresh tokens, and email the owner.

Use go_router

The template navigates with its own stack so it runs unchanged in any app. There are two ways to fit it to go_router.

A. One route (recommended)

Give the whole template a single route, and leave through onAuthenticated. This needs no copying:

final ValueNotifier<Session?> session = ValueNotifier<Session?>(null);

final GoRouter router = GoRouter(
  refreshListenable: session,
  redirect: (BuildContext context, GoRouterState state) {
    final bool signedIn = session.value != null;
    if (!signedIn && state.matchedLocation != '/auth') return '/auth';
    if (signedIn && state.matchedLocation == '/auth') return '/home';
    return null;
  },
  routes: <RouteBase>[
    GoRoute(
      path: '/auth',
      builder: (BuildContext context, GoRouterState state) => Scaffold(
        body: AuthApp(
          resetToken: state.uri.queryParameters['token'],
          recoveryByLink: true,
          onAuthenticated: (Session s) => session.value = s,
        ),
      ),
    ),
    GoRoute(
      path: '/home',
      builder: (BuildContext context, GoRouterState state) =>
          HomePage(onSignOut: () => session.value = null),
    ),
  ],
);

Back inside the template is handled by the template; the system back gesture only reaches go_router when the template is on its first screen.

Localisation

All words are in AuthCopy, and the layouts wrap, mirror for right-to-left and respect large text, so translations drop in. AuthCopy is a set of static members, which have no BuildContext, so connecting gen_l10n is a mechanical change in three steps:

  1. Add the strings to your ARB files (authSignInTitle, authCheckInboxBody(email), …) and run flutter gen-l10n.
  2. Turn AuthCopy into a class that wraps your localisations: 
    class AuthCopy {
  const AuthCopy(this._l10n);
  final AppLocalizations _l10n;

  String get signInTitle => _l10n.authSignInTitle;
  String checkInboxBody(String email) => _l10n.authCheckInboxBody(email);
  String issue(ValidationIssue issue) => switch (issue) {
    ValidationIssue.emailInvalid => _l10n.authEmailInvalid,
    // ...one case per value; the compiler tells you which are missing
  };
}

extension AuthCopyOf on BuildContext {
  AuthCopy get copy => AuthCopy(AppLocalizations.of(this));
}
  3. In the views, replace AuthCopy.signInTitle with context.copy.signInTitle, and remove the const from the widgets that used them. The compiler finds every one.

The domain never contains user-facing text: validators return ValidationIssue values and failures are AuthFailure values, so translating means changing only AuthCopy.

To test your own data source, run the same screens against it: AuthApp(authDataSource: fake) where fake returns the JSON shapes from the contract. Widget tests follow three rules that Cairn’s animations make necessary:

  • Pump in small steps (tester.pump(const Duration(milliseconds: 100))), never pumpAndSettle: the spinner and progress bars repeat and never settle.
  • Advance countdowns with tester.pump(const Duration(seconds: 1)); flutter_test’s fake clock fires the cubits’ timers.
  • Unmount at the end (pumpWidget(const SizedBox.shrink())) so cubits close and timers are cancelled.

test/flutter_test_config.dart loads Geist from ../../fonts when the template sits in the Cairn site checkout. Without a real font, Flutter’s test font draws every glyph as a wide box and reports overflows real text never has; load your own font in the same file and set fontFamily on the test theme.

Troubleshooting

“No AuthScope above this context”

You built a view or ViewModelBuilder outside AuthApp. Mount AuthApp (it provides the scope), or wrap your tree in AuthScope and AuthProviders with a locator from createAuthLocator().

Everything is unstyled

The host app has no CairnTheme. Use CairnTheme.materialTheme(...), or add CairnTheme.light to ThemeData.extensions.

The keyboard covers the field

The template pads its scroll area by the keyboard height, but if your Scaffold has resizeToAvoidBottomInset: false something else must make room: remove that flag, or wrap AuthApp in a Padding of MediaQuery.viewInsetsOf(context).bottom.

The system back button closes my app

That is correct on the template’s first screen; on every other screen back steps through the stack. If back never reaches the template, check that nothing above it (a PopScope, a router) consumes the gesture.

The verify button is dimmed

It waits for six digits, and stays disabled while the code is locked (too many wrong codes, or expired). Requesting a new code clears the lock.

The social buttons sign in as “Taylor”

No onSocialSignIn was given, so the in-memory server received a placeholder token. See Social sign-in.

The keyboard offers no saved passwords

Cairn’s CairnInput does not expose autofillHints, so platform autofill is not offered inside the template. The password keyboard type is set for password fields. If you need autofill, wrap Flutter’s TextField in LabeledInput yourself.

Tests report “A Timer is still pending”

A countdown outlived the test. Unmount the app before the test ends (pumpWidget(const SizedBox.shrink())), or close the cubit through its view model.

Where do I report a bug?

Open an issue on the cairn_site repository with the Flutter and cairn_ui versions.
