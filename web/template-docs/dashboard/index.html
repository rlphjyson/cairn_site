Dashboard template

An analytics dashboard built only from cairn_ui and fl_chart. This guide takes you from copy it in to shipping it with your own data.

Overview

The template is a Flutter package, cairn_template_dashboard, that exposes one widget: DashboardApp. It has a sidebar, a top bar with a period picker (7 days, 30 days, 12 months), and three pages:

  • Overview – four KPI cards with trend badges, a revenue chart against the previous period and the five newest orders.
  • Analytics – a traffic donut, device bars, a visitors line chart and a conversion gauge.
  • Orders – a status filter plus Cairn’s data table with search, sorting and pagination.

It is organised as clean architecture by layer, then by feature, with flutter_bloc for state and get_it for dependency injection. Nothing is generated.

lib/
├─ dashboard_app.dart              entry widget
├─ core/
│  ├─ infrastructure/di/           get_it registration
│  └─ presentation/                charts theme, navigation, ViewModel
├─ common/                         brand constants, formatting, chart scale
├─ data/<feature>/                 remote data sources + repositories
├─ domain/<feature>/               models, mappers, repository interfaces, use cases
└─ presentation/<feature>/         bloc, view models, views, widgets (+ shell/)
The one rule to remember

Dependencies point inwards: presentation → domain ← data. To change where numbers come from you touch data/ and one line of DI. To change how they look you touch presentation/.

Install

A. As a package (recommended)

Keeping it a package means you can pull in fixes later with a version bump.

# pubspec.yaml
dependencies:
  cairn_ui: ^0.2.0
  cairn_template_dashboard:
    git:
      url: https://github.com/rlphjyson/cairn_site.git
      path: templates/dashboard
      ref: main            # pin a tag or commit for production

Or, from a local checkout: path: ../cairn_site/templates/dashboard.

B. Copy the source into your app

  1. Copy templates/dashboard/lib/ into lib/dashboard/ in your app.
  2. Add cairn_ui, fl_chart, flutter_bloc, get_it and equatable to your pubspec.yaml.
  3. Rewrite the package:cairn_template_dashboard/… imports to your app’s package name (a find-and-replace). Files inside the template use relative imports, so only your own references change.
  4. Delete cairn_template_dashboard.dart if you do not want the barrel.
No assets to copy

The dashboard uses no images and no bundled fonts, so there is nothing to declare in pubspec.yaml beyond the dependencies.

Mount it

The template reads colours, radii and type from CairnTheme, so the host app must provide one.

import 'package:cairn_template_dashboard/cairn_template_dashboard.dart';
import 'package:cairn_ui/cairn_ui.dart';
import 'package:flutter/material.dart';

void main() => runApp(const MyApp());

class MyApp extends StatelessWidget {
  const MyApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      title: 'Acme Analytics',
      theme: CairnTheme.materialTheme(CairnTheme.light),
      darkTheme: CairnTheme.materialTheme(CairnTheme.dark),
      home: const Scaffold(body: DashboardApp()),
    );
  }
}

DashboardApp fills whatever space its parent gives it, so put it in a Scaffold body, an Expanded, or a fixed-height box. Each instance creates its own dependency container and disposes it, so two dashboards on one screen never share state.

Change the data

Everything on screen comes from three remote data sources in lib/data/<feature>/remote/. Today they are in-memory stand-ins that return decoded JSON, exactly what an HTTP client would hand you. That makes them the one place to replace.

FileServes
data/overview/remote/overview_remote_data_source.dartKPIs and the revenue series
data/analytics/remote/analytics_remote_data_source.dartTraffic, devices, visits, conversion
data/orders/remote/orders_remote_data_source.dartOrders

JSON shapes

Mappers in domain/<feature>/mappers/ read these keys. The period is passed as week, month or year.

ObjectFields
KPIid, label, value (number), unit (currency | count | percent), delta (percent vs previous period), optional lowerIsBetter (bool)
Revenue pointlabel, current, previous
Traffic sourcelabel, share (percent)
Devicelabel, sessions
Visits pointlabel, visitors, returning
Conversionrate, target (both percent)
Orderid, customer, email, status (paid | pending | failed | refunded), amount, date (ISO-8601)
Chart labels

A chart draws one label per point, so the number of points is up to you. The demo uses 7 for a week, 6 for a month and 12 for a year.

Quick edit without a backend

Open the in-memory data source and change the literals. For example, to rename the first KPI and change its value:

// data/overview/remote/overview_remote_data_source.dart
<String, Object?>{
  'id': 'mrr',
  'label': 'Monthly recurring revenue',
  'value': 48210.0,
  'unit': 'currency',
  'delta': 6.4,
},

Add a KPI

  1. Add another map to the list returned by fetchKpis.
  2. That is all: KpiCards are built from whatever the list contains. The grid reflows to 4, 2 or 1 per row.
  3. Use unit: 'percent' for rates and set lowerIsBetter: true where a falling number is good news (the demo does this for the refund rate).

Add a page

Say you want a Customers page.

  1. Create the feature in each layer: domain/customers/{models,mappers,repositories,use_cases}, data/customers/{remote,repositories}, presentation/customers/{bloc,view_models,views,widgets}. Copy the orders feature and rename.
  2. Register the data source, repository, use cases and a CustomersViewModel in core/infrastructure/di/dashboard_injection.dart (follow the OrdersViewModel lines).
  3. Add customers('Customers') to the DashboardPage enum in core/presentation/navigation/dashboard_navigation_cubit.dart.
  4. Add a case to the switch in presentation/shell/dashboard_shell.dart and an icon in presentation/shell/sidebar.dart.

The compiler guides you: DashboardPage is switched exhaustively, so a missing case is an error, not a blank page.

Brand & theme

Names

The product name, user name, role and avatar initials live in one file:

// lib/common/constants/dashboard_brand.dart
abstract final class DashboardBrand {
  static const String name = 'Acme Analytics';
  static const String userName = 'Ralph B.';
  static const String userRole = 'Owner';
  static const String userInitials = 'RB';
}

To replace the logo tile, edit the Container at the top of presentation/shell/sidebar.dart; an Image.asset works there.

Colours, radius, type

Everything resolves through CairnTheme; there are no hard-coded colours. Change them where you build the theme:

final CairnTheme brand = CairnTheme.light.copyWith(
  primary: const Color(0xFF4F46E5),
  primaryForeground: const Color(0xFFFFFFFF),
  radius: 6,            // every corner rescales from this one number
  fontFamily: 'Inter',
);

MaterialApp(theme: CairnTheme.materialTheme(brand), ...);

Dark mode is a second CairnTheme (CairnTheme.dark.copyWith(...)) passed as darkTheme.

Charts

All charts use fl_chart, restyled by core/presentation/charts/chart_theme.dart: grid lines, axis labels, tooltips and series colours all come from Cairn tokens. The five series colours are CairnColors.chart1…chart5; to use your own palette, edit ChartTheme.series (one function).

ChartWidgetLibrary type
Revenue (area + dashed comparison)presentation/overview/widgets/revenue_chart.dartLineChart
Traffic donutpresentation/analytics/widgets/traffic_donut.dartPieChart
Devicespresentation/analytics/widgets/device_bars.dartBarChart
Visitorspresentation/analytics/widgets/visits_line.dartLineChart
Conversion gaugepresentation/analytics/widgets/conversion_gauge.dartPieChart

Axis maxima come from niceCeil in common/utils/chart_scale.dart, which rounds up to 1, 2, 2.5, 5 or 10 times a power of ten so grid lines land on readable numbers whatever your data is.

Currency formatting ($31,200, 2.5k, +12.5%) is in common/utils/format.dart; change DashboardFormat.currency for euros, rupees or locale-aware output with intl.

Connect a backend

Implement the same interface the in-memory source does, then swap one DI line. Here is a REST version of the orders source using package:http:

// lib/data/orders/remote/http_orders_remote_data_source.dart
import 'dart:convert';

import 'package:http/http.dart' as http;

import 'orders_remote_data_source.dart';

class HttpOrdersRemoteDataSource implements OrdersRemoteDataSource {
  HttpOrdersRemoteDataSource(this._client, {required this.baseUrl, this.token});

  final http.Client _client;
  final String baseUrl;
  final String? token;

  @override
  Future<List<Map<String, Object?>>> fetchOrders() async {
    final http.Response res = await _client.get(
      Uri.parse('$baseUrl/orders'),
      headers: <String, String>{
        if (token != null) 'Authorization': 'Bearer $token',
      },
    );
    if (res.statusCode != 200) {
      throw http.ClientException('Orders failed: ${res.statusCode}');
    }
    return (jsonDecode(res.body) as List<Object?>)
        .cast<Map<String, Object?>>();
  }
}

Register it in core/infrastructure/di/dashboard_injection.dart in place of the in-memory one:

g.registerLazySingleton<OrdersRemoteDataSource>(
  () => HttpOrdersRemoteDataSource(
    http.Client(),
    baseUrl: 'https://api.example.com',
  ),
);
Errors and loading are handled

If a data source throws, each cubit keeps whatever it already showed and sets failed: true; on a first load the page shows an ErrorPanel (a destructive CairnAlert with a Try again button). Loading shows a CairnSpinner. To surface the actual message, add a field to the state in the cubit’s catch block and pass it to ErrorPanel(message: …).

If your API names fields differently, change the mapper (domain/<feature>/mappers), not the views. If it returns a different period vocabulary, translate in the repository (period.name is the only place the period leaves the app).

Use go_router instead

The template has its own tiny navigation cubit so it runs in any app. In a real product you probably want URLs.

  1. Add go_router and define one route per DashboardPage.
  2. In sidebar.dart and the compact _PageSwitcher in dashboard_shell.dart, replace context.read<DashboardNavigationCubit>().select(p) with context.go('/${p.name}') and read the active page from the router.
  3. Render the page from the route’s builder instead of the switch in DashboardShell; keep the shell as a ShellRoute so the sidebar persists.
ShellRoute(
  builder: (context, state, child) => DashboardFrame(child: child),
  routes: [
    GoRoute(path: '/overview',  builder: (_, __) => const OverviewView()),
    GoRoute(path: '/analytics', builder: (_, __) => const AnalyticsView()),
    GoRoute(path: '/orders',    builder: (_, __) => const OrdersView()),
  ],
)

Every view already works standalone: they read the period from PeriodCubit and resolve their own view model.

Testing

cd templates/dashboard
flutter pub get
flutter analyze --fatal-infos --fatal-warnings
flutter test

The suite has three layers: domain (formatting, axis scale, filters, KPI rules), session (cubits through the real container, no widgets) and widget tests that mount DashboardApp at 1200, 900 and 390 pixels. Use small tester.pump(Duration) steps, never pumpAndSettle: Cairn has repeating animations, so it would never return.

When you replace a data source, keep the in-memory one for tests and register it in a test container.

Deploy (Flutter web)

  • flutter build web --release. If you host under a sub-path, add --base-href /your-path/.
  • Single-page apps need a fallback so refreshes do not 404. On GitHub Pages copy index.html to 404.html; on Netlify/Firebase add a rewrite to /index.html.
  • Charts and tables are drawn with the canvas renderer; for large order sets, page on the server and pass one page at a time to CairnDataTable.

Migration notes

When you…Do this
Upgrade cairn_ui to a new minorBump the constraint, run flutter analyze. Components added in a minor never break this template; read the library’s CHANGELOG for renames.
Move from copied source to the packageDelete your copy, add the dependency, change imports back to package:cairn_template_dashboard/…, move your edits (usually only data sources and DashboardBrand) into your own wrapper.
Pull template updates into a copyDiff templates/dashboard/lib between your last sync tag and the new one; because dependencies point inwards, changes are almost always inside a single layer.
Change state managementCubits are plain streams of immutable states. Views only call vm.cubit.method() and read state, so Riverpod or Provider can replace BlocBuilder view by view.

Troubleshooting

“No DashboardScope above this context”

You built a view or ViewModelBuilder outside DashboardApp. Mount DashboardApp (it provides the scope) or wrap your tree in a DashboardScope with a locator from createDashboardLocator().

Everything is black/white and unstyled

The host app has no CairnTheme. Use CairnTheme.materialTheme(...) or add CairnTheme.light to ThemeData.extensions.

“RenderFlex overflowed” in tests

Flutter’s test font is wide. Load your real font in test/flutter_test_config.dart (the template does this for Geist when it finds it) and set fontFamily on the test theme.

Charts jump when the period changes

They do not by default: each screen keeps the old figures until the new ones arrive, then fl_chart animates between them. If you see a flash, check that your cubit does not emit a loading state with empty lists.

Where do I report a bug?

Open an issue on the cairn_site repository with the Flutter and cairn_ui versions.
