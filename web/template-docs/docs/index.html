Documentation template

A documentation site built only from cairn_ui: sidebar, versions, command-palette search, typed content blocks and an on-this-page rail. This guide takes you from installing it to deploying your own docs.

Flutter web, mobile and desktopcairn_ui ^0.2.0flutter_bloc + get_itWorks offline

#1. Overview and architecture

The documentation template is a complete docs site as one Flutter package. A top bar carries the brand, a version selector and a search button that opens a command palette. A sidebar lists collapsible sections of pages and turns into a drawer below 900 px. The article area renders typed content blocks (headings, paragraphs with inline markup, code with a copy button, callouts, tabs, steps, tables and lists), an On this page rail follows the scroll above 1100 px, and previous / next links close every page.

It is built only from cairn_ui components and tokens, so it follows your CairnTheme in light and dark with no colour of its own. The sample content documents a fictional “Acme SDK” with four sections and thirteen pages in two versions; replacing it is the main thing you will do.

The layers

  presentation/                       what the reader sees
  │  docs/      bloc, view_models, views, widgets   (article, blocks, toc rail, pager)
  │  search/    SearchCubit, command palette
  │  sidebar/   SidebarCubit, page tree
  │  shell/     providers, top bar, responsive frame
  │                       │ depends on
  ▼                       ▼
  domain/                             plain Dart, no Flutter
     docs/      models, mappers (JSON -> models), repositories (interface), use_cases
     search/    models, use_cases
  ▲
  │ implements
  data/
     docs/remote/       DocsRemoteDataSource + in-memory content  <-- replace this
     docs/repositories/ DocsRepositoryImpl (maps JSON, caches a version)

  core/    DI container, DocsNavigationCubit, ViewModel, DocsScope, DocsHost
  common/  constants (brand, links, layout), utils (inline markup, slugify, dates)

How a page gets on screen

  1. DocsApp builds its own GetIt container and asks DocsCubit to load the version in DocsNavigationCubit.
  2. DocsCubit calls the GetVersions and GetDocsSite use cases. The repository fetches decoded JSON from the data source and hands it to DocsMapper, which returns a DocsSite: the sidebar tree plus every page as typed DocBlocks.
  3. DocsProviders sees the new site and tells SearchCubit to index it.
  4. DocPageView looks up the open page and mounts it with a DocPageViewModel, which owns the scroll controller, the heading keys and the cubit that tracks the active heading.

The rules

  • Dependencies point inwards: presentation and data depend on domain, domain depends on nothing.
  • Views never touch the container. Screen-scoped state comes from ViewModelBuilder<T>; session cubits are read with context.read.
  • Session cubits (navigation, docs, search, sidebar) are lazy singletons that only the container closes. Screen cubits (the table-of-contents cursor) are owned and closed by a view model.
  • No code generation. Registrations are written out in core/infrastructure/di/docs_injection.dart.
  • The template has its own navigation, so it runs inside any host and has no router dependency.

#4. Mount it

A complete main.dart. The template takes its colours from the ambient CairnTheme, which CairnTheme.materialTheme registers as a theme extension, so build your MaterialApp theme that way.

url_launcher is your dependency, not the template’s; leave onOpenExternal out until you add it.

DocsApp parameters

Embedding it in a bigger layout

DocsApp sizes itself to its parent and makes every responsive decision from its own width, not the window’s. Put it in an Expanded, a card or a phone mock-up and it adapts: fixed sidebar from 900 px, table-of-contents rail from 1100 px, drawer and compact top bar below.

Toasts. DocsApp installs its own CairnToaster inside its frame, so the copy confirmation works without any host setup. If your app already has one above the navigator, the nearest one wins.

Block reference

Every block has a type. The text fields marked inline accept the inline markup **bold**, `code` and [text](target), where target is an external URL (https://, mailto:), another page (quick-start), a heading on another page (authentication#scopes), or a heading on this page (#scopes). An unmatched marker stays as literal text and never throws.

typeFieldsRenders as
headingtext, level (2 or 3, default 2), id (default: slug of the text; repeats get -2, -3)An h2 / h3 with a hover # link. Appears in the table-of-contents rail and in search.
paragraphtext (inline)Body text, 16 px on a 1.7 line height.
codecode, language (dart, yaml, bash, json, anything else is plain), titleA bordered block with the title or language in the header, a copy button (toast on success), horizontal scrolling and syntax colours.
calloutkind (info, tip, warning), title, text (inline)A CairnAlert. Info and tip differ by icon; warning uses the destructive variant.
tabstabs: list of {label, blocks}A CairnTabs bar over the selected tab’s blocks. Any block may go inside, including code.
stepssteps: list of {title, blocks}A numbered vertical procedure with a hairline joining the markers.
tableheaders: list of strings, rows: list of lists of strings (inline)A CairnTable in a bordered frame; scrolls sideways when the columns cannot fit at 140 px each.
listitems: list of strings (inline), ordered (default false)Bullets or numbers with a hanging indent.
Headings inside tabs and steps are not anchors: only the selected tab is on screen, so they cannot be scrolled to reliably. Use top-level headings for anything the rail or search should reach.

Versions

The manifest lists the versions the selector shows. Each is {id, label, latest?, notice?}:

  • Exactly one version is latest; it gets a “(latest)” suffix and is where the “Switch to…” button in an old version’s banner leads.
  • A notice makes a banner appear above every page of that version.
  • Add a branch for the new id in InMemoryDocsRemoteDataSource.fetchSite (or serve it from your own data source) returning that version’s sidebar and pages.
  • Set DocsBrand.defaultVersionId in common/constants/docs_brand.dart to the new latest id. The domain test the default version is the latest one fails if you forget.

Switching version keeps the reader on the same page when the new version has it. When it does not, they see a “Page not found” state that names the version and offers a button to the first page, so a deep link never dead-ends silently.

Search

Search needs no configuration: SearchDocs indexes every page title, description and h2 / h3 heading of the loaded version when it loads. The palette (button, Ctrl+K, Cmd+K or /) lists pages grouped by sidebar section and headings as Page › Heading. Choosing a heading opens its page and scrolls to the anchor. To index body text as well, add more keywords to the hits in domain/search/use_cases/search_docs.dart.

#7. Branding and theming

The template draws nothing with a hard-coded colour. Every surface, border and text colour comes from CairnTheme, so rebranding is a theme change in your app, not an edit of the template.

Theme, fonts and radius

Declare the font in your pubspec.yaml as usual. Code uses a monospace stack (ui-monospace, SFMono-Regular, Menlo, Consolas, monospace) defined as monoFallback in core/presentation/docs_text.dart; change it there if you bundle a mono font.

Brand name and logo

  1. Set DocsBrand.name, tagline and monogram in common/constants/docs_brand.dart.
  2. For a real logo, replace the DecoratedBox in core/presentation/widgets/brand_mark.dart:

Code colours

Cairn’s palette is achromatic, so the syntax colours are the one place the template adds hue. They are oklch() triples in presentation/docs/widgets/syntax.dart, converted with the same Oklch.toColor Cairn uses, and tuned to clear 4.5:1 on the code surface in both themes. Edit SyntaxTheme.light and SyntaxTheme.dark to match your brand. The tokeniser is deliberately small (comments, strings, numbers, keywords, capitalised identifiers); swap highlight() for a real lexer if you need more languages.

Typography and spacing

The reading column is 720 px (DocsLayout.contentMaxWidth), body text is 16 px on a 1.7 line height, h2 is 24 px with 48 px above it, and blocks are separated by 20 px. Those numbers live in block_column.dart, heading_view.dart and page_header.dart.

#8. Use go_router with deep links

The template navigates on its own, so it has no router dependency and works inside any host. To put the location in the URL (so a reader can share /docs/v2.0/configuration#environments and the back button works), connect onLocationChanged and initialLocation to your router. Add go_router to your app; the template does not need it.

How the two stay in step

  • A click in the template changes DocsNavigationCubit; DocsProviders calls onLocationChanged; your router updates the URL and rebuilds DocsApp with a new initialLocation.
  • In didUpdateWidget, DocsApp calls navigation.go(location). When the location equals the one it is already at, that is a no-op, so there is no loop.
  • A pasted URL or the back button changes initialLocation first, and the template follows.
  • A headingId in the location scrolls the page to that heading, on first open and on later changes.
Paths without a hash. On the web, Flutter defaults to hash URLs (/#/docs/...). Call usePathUrlStrategy() from package:flutter_web_plugins/url_strategy.dart in main before runApp for clean paths, then configure your host as described under Deploy.

Replacing the navigation cubit instead

If you would rather delete DocsNavigationCubit and let the router be the source of truth, keep DocsLocation and make the cubit a thin adapter: its openPage, goToHeading and selectVersion become calls to context.go(...), and its state is derived from GoRouterState. Every view only calls those three methods and reads state.pageSlug, versionId, headingId and jump, so no screen changes. The callback approach above is less work and is the one the tests cover.

#9. Deploy and SEO for Flutter web

Build

The --base-href value must start and end with a slash and match where you serve the files. A wrong base href is the usual cause of a blank page with 404s for main.dart.js in the console.

404 fallback

With path URLs (see usePathUrlStrategy() above), a reload on /docs/v2.0/configuration asks the server for a file that does not exist. Tell the host to answer every unknown path with index.html:

HostSetting
Firebase Hosting"rewrites": [{"source": "**", "destination": "/index.html"}] in firebase.json
Netlify, Cloudflare PagesA _redirects file containing /* /index.html 200
GitHub PagesCopy build/web/index.html to build/web/404.html after building
nginxtry_files $uri $uri/ /index.html;

If you keep the default hash strategy no server setup is needed, at the price of uglier URLs.

An unknown page is not a 404 to a crawler. The fallback serves index.html with status 200 and the template shows its “Page not found” state inside it. That is fine for readers; search engines may index such URLs as soft 404s.

SEO

Flutter web renders to a canvas, so a crawler that does not run JavaScript sees only index.html. Be honest about this when choosing the template: it is a good fit for logged-in, internal and developer-audience docs, and a weaker one for content that depends on organic search. Mitigations, in order of effort:

  1. Edit web/index.html: a real <title>, <meta name="description">, Open Graph tags and a canonical link.
  2. Publish a sitemap.xml and robots.txt next to index.html. Generate the sitemap from the same content (the DocsSite gives you every slug).
  3. Update document.title per page from onLocationChanged (for example with SystemChrome.setApplicationSwitcherDescription or a small dart:js_interop call).
  4. Pre-render or serve static HTML for crawlers from the same JSON (a build script that walks docsManifest and writes one HTML file per page is about fifty lines), and let people land on the Flutter app.

Performance

Use --release (the default CanvasKit renderer), serve with gzip or brotli, and give main.dart.js and the font files long cache lifetimes. The in-memory content ships inside main.dart.js; a CMS keeps it out.

#10. Testing

The template ships three kinds of test. Run them from the package folder:

FileCovers
test/domain_test.dartThe inline-markup parser, slugify, every mapper branch and error, the seed content (twelve or more pages, every internal link resolves to a real page and heading), heading extraction, previous / next, and search.
test/session_test.dartThe cubits through the real container with no widgets: navigation, loading and failing, stale-request protection, search indexing, sidebar, scoping rules.
test/docs_app_test.dartDocsApp mounted at 390, 768 and 1280 px in light and dark: navigating, collapsing, previous / next, palette search with scroll to a heading, Ctrl+K, version switching, copy with toast, tabs, the rail, the drawer, loading, error and not-found states.

Writing your own widget test

test/support/harness.dart has pumpDocs, which mounts the app in a themed MaterialApp at a given size and returns the list of strings written to the clipboard. Two rules it follows, which you should too:

  • Never pumpAndSettle. Cairn’s skeleton and spinner animate forever, so the tree never goes idle and the call times out. Pump in small steps (settle(tester) pumps eight 100 ms frames).
  • Pump a little extra after navigation. Collapsing sections and the page fade finish a few frames later.

Buttons merge their visible text into their semantics label, so the harness’s sem() matches by prefix; and docsTest turns semantics on for the test.

Fonts in tests. flutter test draws every glyph as an identical box unless a font is loaded, which hides real overflow. test/flutter_test_config.dart loads Geist from ../../fonts when it exists; point it at your font files for accurate layout assertions. Code also renders as boxes unless a monospace face is loaded.

Testing your content

The “every internal link resolves” test in domain_test.dart walks every block of both versions. When you replace the content, keep it: it turns a renamed page or heading into a failing test instead of a dead link.

#11. Troubleshooting and FAQ

The page is blank and the console shows 404s for main.dart.js.
The --base-href does not match where the files are served. See Build.
Reloading a deep link gives a server 404.
You are using path URLs without a rewrite rule. See 404 fallback, or keep hash URLs.
Text is unstyled, with a yellow underline.
That is Flutter’s “no Material ancestor” style. DocsApp wraps itself in a transparent Material and a DefaultTextStyle, so you only see it if you built your own shell around its widgets without DocsApp.
Colours are wrong, or everything is the light theme.
CairnTheme.of falls back to CairnTheme.light when the theme has no Cairn extension. Build your ThemeData with CairnTheme.materialTheme(...) as shown in Mount it.
The copy toast does not appear.
The toaster is installed by DocsApp inside its frame. If you rebuilt the shell yourself, wrap it in a CairnToaster. In a test, copy works but the toast is only visible for two seconds of fake time.
The palette or drawer shows unthemed.
They are routes on the root navigator, so they take the theme from your MaterialApp, not from the template. Make sure the theme is set on the app that owns the navigator, not on a widget below it.
A page shows “Could not load the documentation”.
The text under it is the exception. A FormatException from the mapper names the page and block; fix the content and press Try again.
Clicking a link inside a paragraph does nothing.
Check the target. Internal targets are slugs of the current version; an unknown one opens the not-found state. External targets go to onOpenExternal, or are copied when you did not supply one.
Why can’t I tab to links inside paragraphs?
Inline links are tappable text spans, and Flutter cannot focus a span. Every navigational target also exists as a focusable control (sidebar, breadcrumb, previous / next, table of contents). If you need keyboard access to inline links, render them as WidgetSpan(CairnLink(...)) in rich_inline.dart, accepting that a long link then cannot wrap.
The table of contents highlights the wrong heading near the bottom.
On the last screenful the last headings can never reach the top, so the last entry is highlighted once you reach the end. That is intended.
I added a heading in a tab and it is not in the rail or search.
Only top-level headings are anchors. See the note under Block reference.
Two copies of the template on one screen?
Fine. Each DocsApp builds its own container, so they share no state.
How do I hide the version selector?
Return a single version from the manifest; the selector then offers one option. To remove the control, delete _VersionSelect from presentation/shell/top_bar.dart.
How do I add a language to the highlighter?
Add a value to CodeLanguage in doc_block.dart (and its parse aliases), then a keyword set and a branch in highlight() in syntax.dart.

#12. Migration notes

Upgrading cairn_ui

The template is tested against cairn_ui 0.2.0. Bump the constraint, run flutter analyze and flutter test, and look first at these coupling points:

Cairn componentUsed inWatch for
CairnAlertcallout_view.dart0.2 has only normal and destructive variants, so info, tip and warning are told apart by icon and title. If a later release adds info / warning variants, map CalloutKind to them here.
CairnCommand, showCairnCommandPalettesearch_palette.dartFiltering is done by the widget (label, group and keywords), not by SearchDocs. A change to its matching changes search results.
CairnSheet, showCairnSheettop_bar.dartThe drawer is a left sheet on the root navigator.
CairnSelecttop_bar.dartThe version selector; width, size and semanticLabel.
CairnTabs, CairnTable, CairnBreadcrumbblock views, page_header.dartConstructor and sizing changes. Table cells are built with CairnColumn.cell.
CairnToaster, CairnToast.showdocs_shell.dart, code_block_view.dartThe toast is found through an ancestor, so the toaster must stay above the code block.
CairnTheme tokenseverywhereRenamed or removed tokens fail to compile, which is the point of using only tokens.

Changing the content format

If you change a block’s JSON, change three places together: the model in doc_block.dart, the case in DocsMapper.block, and the case in block_column.dart. DocBlock is sealed, so the renderer’s switch will not compile until every subtype is handled. Add a case to the “maps every block type” test.

Template versions

This is version 1.0.0 of the template.

  • DocsApp’s public surface is its four parameters and DocsLocation. Treat everything else as yours to edit.
  • If you copied lib/ you will not receive upstream changes automatically; diff the template folder when you bump cairn_ui.
  • Moving from the in-memory data source to your own is the only migration most projects ever need, and it touches no screen.
This page is self-contained: no external requests, light and dark by system setting, and print-friendly. The code samples were checked against the package: the Markdown converter and data source are compiled and run against the template’s mapper in a test.
